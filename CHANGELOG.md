# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Начиная с `0.11`, публичные версии имеют вид `X.Y`, а Cargo хранит `X.Y.0`; пока старшая цифра равна нулю, совместимость не обещается. Каждый PR добавляет строку в раздел «Не выпущено», при выпуске раздел становится версией. Как выпустить версию — в `docs/ru/developer/guides/release.md`.

## Не выпущено

### Changed

- Restored the README logo and added a short explanation of OSel's purpose: learning how operating systems and PCs work.
- All pull requests and releases must be written in English; the PR template and contributor instructions now reflect this rule.
- Simplified the English README to the project name, description and documentation link.

## 0.11 — 2026-10-15

### Added

- Command history: recall the last 64 commands with Up/Down and restore unfinished input.
- Colored scrollback: browse 1,024 output lines with PageUp/PageDown or Ctrl+Shift+Up/Down; Escape or typing returns to live output.
- Network Tetris with DHCP/IPv4/TCP and Intel 82574L and Realtek Ethernet support.

### Fixed

- Slow console scrolling: keep text in RAM, redraw changed cells without reading video memory, and batch `cat` output.

### Changed

- Tetris preserves the shell on an alternate screen and keeps game frames out of scrollback.
- Hardware drivers are grouped under `src/drivers/`; documentation is available in Russian and English with a native language selector.
- Releases use `X.Y` version numbers and concise English descriptions; Cargo stores `X.Y.0`.

## 0.1.0 — 2026-10-14

Первый GitHub Release с готовыми загрузочными образами: ядро x86_64, интерактивная оболочка и одиночный тетрис на Go.

### Добавлено

- Автоматический GitHub Release по тегу `vX.Y.Z`: готовые UEFI- и BIOS-образы с оболочкой, тетрисом, `clear` и лицензией шрифта, контрольные суммы SHA-256. Перед публикацией оба образа проходят проверку загрузки и программ в QEMU; инструкция для флешки начинается со скачивания готового образа без Rust и Go.
- Интерактивная оболочка `osel>` вместо автозапуска игры: `help`, `ls`, `cat`, запуск программ из `/bin`, внешний `clear`, повторный `tetris` с возвратом. Ограниченный редактор строки, восстановление терминала и сквозная проверка COM1/PS2 в QEMU.
- Дочерние программы из Go через `os/exec`: PID, `clone` с `vfork`, `execve`, `wait4`, каналы, наследование дескрипторов и `CLOEXEC`; внешняя утилита `/bin/clear`. Проверены ошибки запуска, коды выхода, передача данных и освобождение ресурсов.
- Одиночный тетрис на Go в ramdisk с запуском из оболочки: закреплённый submodule, ввод COM1/PS2, режимы `/dev/tty` через `ioctl`, ANSI-очистка, курсор и цвета framebuffer. Автотест QEMU нажимает клавиши и проверяет ответы игры; внешний `clear` сохранён.
- Набор тестов-атак (`src/security.rs`): враждебные программы пытаются достать память ядра и чужих процессов, передают плохие указатели и наводняют ядро потоками — ядро устаивает, утечек нет. Страница [изоляция программ](https://vszholobov.github.io/OSel/ru/developer/architecture/core/security.html).
- Запуск программ на Go: статический бинарник Go печатает, крутит горутины и `time.Sleep` и выходит. Добавлены системные вызовы `clone`, `futex`, `nanosleep`, `clock_gettime`, `epoll_create1`, `epoll_ctl`, `epoll_pwait`, `eventfd2`, `gettid`, `arch_prctl`, `sched_getaffinity`, `getrandom`, `prlimit64` и заглушки сигналов (`rt_sigaction`, `rt_sigprocmask`, `sigaltstack`, `tgkill`, `prctl`); монотонные и реальные часы, сон до срока, разделяемое потоками адресное пространство и дескрипторы. Runner собирает `user-go/gohello` хостовым `go`, сквозной тест `tests/go_hello.rs` его запускает.
- Память для программ: `mmap` анонимной памяти с подсказкой адреса и `MAP_FIXED`, `munmap`, `mprotect`, `madvise` (`MADV_DONTNEED` даёт нули); страницы появляются при первом обращении, поэтому резервы `PROT_NONE` ничего не стоят; ядро так же отображает нетронутые страницы буфера системного вызова.
- Потоки и вытеснение: у каждого потока свой стек ядра со страницей-охранником, таймер переключает потоки по кругу на каждом тике, x87, SSE и база FS переключаются вместе с потоком; процессы с `kill` и ожиданием, поток простоя, потоки ядра, вызов `sched_yield`.
- Файлы для программ: дескрипторы (`FdTable`, описания открытых файлов с общим смещением), `openat`, `read`, `close`, `fstat`, `newfstatat`, `fcntl`; каталог `/dev` с `null` и `tty`; дескрипторы 0–2 на терминале, который читает клавиатуру и пишет на экран и в порт.
- SSE и x87 для программ: ядро само включает их в CR0 и CR4 (под BIOS их не включал никто), каждая программа начинает со сброшенного состояния и сохраняет свои регистры `fxsave64`; ошибки x87 и SSE завершают программу.
- Системные вызовы Linux через `syscall`: `write` на экран и в последовательный порт, `getpid`, `exit`, `exit_group`; справочник `docs/ru/developer/reference/syscalls.md`, который сверяет `cargo docs-check`. Runner собирает программы из `user/` и кладёт их в `/bin` ramdisk; ядро при загрузке запускает `/bin/hello`.
- Пользовательский режим: сегменты кольца 3 в GDT, изменяемый TSS, `user::run` входит в программу через `iretq` и возвращается при её исключении со всеми регистрами в `TrapFrame`; исключение программы её завершает, а не ядро. Проверка адресов, переданных программой (`copy_from_user`, `copy_to_user`).
- Загрузка программ: свой парсер статических ELF64 (`osel-core/src/elf.rs`) загружает сегменты в обнулённые страницы `UserSpace`, `program::load` отображает стек и собирает стартовый стек с argv, envp и auxv по System V ABI. Коды ошибок `ENOEXEC` и `E2BIG`.
- Адресные пространства программ: `AddressSpace` в `osel-core` и `UserSpace` в ядре — своя нижняя половина, общая с ядром верхняя; удаление возвращает все страницы в пул. `map_range` обнуляет страницы и при ошибке откатывает всё, что успел сделать, `unmap_range` снимает страницы и освобождает опустевшие таблицы.
- Освобождение физических страниц: `FrameSource` и `FramePool` в `osel-core` — освобождённые страницы выдаются снова в порядке LIFO, двойное освобождение и чужая страница дают панику. Каждый тест ядра проверяет утечки страниц (`testosterone::forbid_frame_leaks`).
- Ramdisk: runner упаковывает папку `ramdisk/` (или `OSEL_RAMDISK`) в архив cpio, ядро монтирует его как корень `/` и печатает `/etc/motd` при загрузке. Интерфейсы `BlockDevice`, `FileSystem`, `Inode` и коды ошибок Linux `Errno` в `osel-core` — под будущие диски и файловые системы.
- Документация в `docs/` на Diplodoc: разделы для пользователя, рецепты, устройство, справочник, решения и планы. Сайт собирается в CI и публикуется на GitHub Pages.
- Инструкции для ИИ-агентов: `AGENTS.md`, `CLAUDE.md`, правила по папкам и навыки в `.claude/`.
- `cargo docs-check`: тесты, что документация не разошлась с кодом.
- Версия и коммит ядра при загрузке и на экране падения.
- Шаблон PR и этот журнал изменений.
- Загрузка через UEFI и BIOS на `bootloader` 0.11, ядро в верхней половине адресов.
- Вывод текста в framebuffer, последовательный порт, клавиатура PS/2.
- Аппаратные прерывания, таймер 100 Гц, обработка ложных IRQ 7/15.
- Страничная память, аллокатор физических страниц и куча ядра.
- Обработчики всех исключений процессора и красный экран падения с регистрами.
- Блокировки `IrqSpinlock`, которые сами выключают прерывания и сообщают о взаимоблокировке.
- Тесты: в `osel-core` на хосте, у runner, в QEMU для ядра и интеграционные; проверка утечек кучи после каждого теста.
- CI: тесты на хосте, QEMU в режимах UEFI и BIOS, запуск настоящего ядра, еженедельная проверка свежего nightly.

### Изменено

- В консоли framebuffer — более широкий шрифт OSel Console на основе Terminus с готовым растром 16×32 вместо увеличенного 14×36, без лишнего межстрочного зазора. На маленьком экране используется 8×16. QEMU предлагает экран 1280×1024; лицензия шрифта включена в репозиторий и ramdisk.
- Куча ядра выросла с 1 до 16 МБ.
- Логотип OSel (осёл в визоре с командной строкой) в шапке сайта, иконке вкладки и README; в шапке одна надпись «Операционная система OSel».

### Исправлено

- PS/2-клавиатура после UEFI: явная настройка i8042, набора скан-кодов и передачи нажатий вместо зависимости от прошивки; ограниченные ожидания и резервный опрос при пропавшем IRQ 1. Автоматическая экранная диагностика и команда `kbd` показывают этап инициализации и счётчики ввода. Проверка исправления на Lenovo Xiaoxin Pro 14 ещё требуется.
- Медленный отклик тетриса при удержании клавиш: независимое обновление экрана до 30 кадров/с, вывод только изменившихся участков, короткие критические секции терминала и ускоренная отрисовка глифов и очистка framebuffer. Следующая фигура показана рисунком вместо номера.
- Интерактивный runner сразу выводит кадры без перевода строки, не задерживая их в буфере stdout.
- Документация подведена к завершённому этапу 2: отмечен запуск Go, убраны закрытые пункты техдолга, актуализированы потоки и системные вызовы; план этапа заменён ссылками на PR и устройство подсистем.
- На сайте документации не было верхнего меню, а с ним и поля поиска.
- В шапке сайта не показывался логотип, а надпись не совпадала по краю с оглавлением.
- Обработчики исключений 28 (`hv_injection_exception`) и 29 (`vmm_communication_exception`): раньше они давали «SEGMENT NOT PRESENT» вместо своего названия.
