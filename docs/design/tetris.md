# Тетрис на Go

**Для кого:** для тех, кто работает над этапами 3 и 4: терминал и сеть.

**Коротко:** [тетрис](https://github.com/vszholobov/Tetris) — сетевая игра, в которой клиент только рисует поле и передаёт нажатия, а вся игра идёт на сервере. Для OSel нужен одиночный режим в самом тетрисе и небольшая правка очистки экрана. От ядра нужны `/dev/tty` с режимами терминала, блокирующее чтение, таймеры и шесть управляющих последовательностей на экране.

## Как устроен тетрис сейчас

- `client/` рисует поле и отправляет нажатия по websocket; `server/` ведёт игру.
- Логика поля — `server/field` (поле в `math/big`), игровой цикл — `processGameField` и `inputControl` в `server/server/session.go`.
- `lib/` — общие типы клиента и сервера.

## Что поменять в тетрисе

- **Одиночный режим.** Перенести `server/field` в `lib/`, а игровой цикл (`processGameField`, `inputControl`, около 60 строк) — в клиент. Клиент вызывает свою `PrintSelfField` напрямую, без сети.
- **Очистка экрана.** Сейчас `client/keyboard/keyboard.go` запускает внешнюю программу `clear`. Для OSel это потребовало бы запуска программ, файловой системы и базы терминалов. Замена — одна строка: `fmt.Print("\033[H\033[2J")`.
- **Буква «Ж».** Фигуры рисуются кириллической буквой. В шрифте консоли OSel кириллицы нет, на реальном экране будет знак замены. Варианты: шрифт с кириллицей в консоли (PSF, например Terminus) или `#`/`█` вместо «Ж».
- **Сборка:** `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build`.

## Что тетрис требует от ядра

**Терминал** (библиотека [mattn/go-tty](https://github.com/mattn/go-tty), файл `tty_unix.go`):

- Открывает `/dev/tty` дважды: на чтение и на запись. Ядру достаточно узнавать этот путь, файловая система не нужна.
- Читает и меняет режим через `ioctl`: `TCGETS`, `TCSETS`, размер окна — `TIOCGWINSZ`. Выключает эхо и построчный ввод (`ECHO`, `ICANON`), читает по одному символу (`VMIN = 1`).
- Ждёт клавишу в отдельной горутине: поток должен засыпать до прихода символа.

**Управляющие последовательности** — на экране их нужно понимать в консоли OSel, через последовательный порт их понимает терминал на хосте:

| Последовательность | Действие |
|---|---|
| `\033[22A` | курсор вверх на N строк |
| `\033[1B` | курсор вниз |
| `\033[36C` | курсор вправо |
| `\r` | в начало строки |
| `\033[?25l` / `\033[?25h` | скрыть / показать курсор |
| `\033[H\033[2J` | очистка экрана (после правки `clear`) |

**Рантайм Go:**

- Таймер падения фигуры — `time.After`. Таймеры Go работают через тот же механизм ожидания событий (netpoller, `epoll`), что и сеть: нужен хотя бы сон с тайм-аутом и пробуждение.
- `/dev/tty` Go пытается зарегистрировать в `epoll`. Если `epoll_ctl` ответит `EPERM`, Go перейдёт на обычное блокирующее чтение — полноценный `epoll` для тетриса не нужен.
- Несколько горутин, значит несколько потоков: нужны `clone` и `futex`.
- Генератор фигур инициализируется временем, рантайм при старте просит случайные байты: нужны часы и `getrandom`.
- `signal.Notify` для Ctrl+C: на первое время достаточно принять подписку, доставку сигналов можно сделать позже. Ctrl+C декодер клавиатуры уже выдаёт как `\x03` (`osel-core/src/keyboard.rs`).
- Переменная `CLEAN_ROWS_COUNT` читается, но без неё берётся значение по умолчанию: пустое окружение подходит.

## Сетевой вариант (этап 4)

- Клиент подключается по `ws://` и `http://`, без TLS: нужен только TCP.
- Адрес сервера можно прописать в `/etc/hosts` внутри ramdisk: тогда Go не пойдёт к DNS и не нужен UDP.
- Websocket и HTTP Go делает сам, ядро передаёт байты.
- Нужны: перебор устройств PCI, драйвер сетевой карты (сначала Intel `e1000e` в QEMU), стек [smoltcp](https://github.com/smoltcp-rs/smoltcp), сокеты и полноценный `epoll`.

**Почему без Wi-Fi.** У каждой Wi-Fi-карты свой сложный драйвер (у Intel в Linux больше 100 тысяч строк), закрытая прошивка, которую драйвер загружает в карту, и отдельный протокол подключения и шифрования (WPA2/WPA3). Это больше всей остальной системы. Проводная карта на порядок проще: драйвер около тысячи строк и открытая документация. Какая карта стоит в машине, видно в Диспетчере устройств Windows (раздел «Сетевые адаптеры»); машины описаны в [справочнике](../reference/hardware/samsung-np530u4b.md).
