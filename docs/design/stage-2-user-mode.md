# Этап 2: пользовательский режим и программы на Go

**Для кого:** для разработчика или агента, который начинает задачу этапа 2.

**Коротко:** этап 2 должен запустить статическую Go-программу «hello world» с горутинами и `time.Sleep`. Ниже — что нужно сделать, в каком порядке и какие ловушки известны заранее. Когда этап закроется, содержимое этой страницы переедет в `architecture/` и решения, а здесь останется ссылка (правило — в [«Как писать документацию»](../guides/writing-docs.md#single-home)).

Перед началом прочитайте: [память](../architecture/core/memory.md), [прерывания](../architecture/core/interrupts.md), [блокировки](../architecture/core/locking.md), решения [0005](../decisions/0005-linux-abi-for-go.md) и [0006](../decisions/0006-higher-half-kernel.md).

## Порядок работы

1. Подготовка, без новых подсистем: GDT и TSS, куча, освобождение физических страниц, зануление страниц для программ, таблицы верхней половины, ramdisk, SSE.
2. Адресное пространство как тип; отображение страниц программ.
3. Вход в ядро: данные на процессор в GS, регистры `syscall`, заглушка входа на ассемблере.
4. Загрузчик ELF и стартовый стек. **Проверка:** программа на ассемблере печатает «hello» через `write` и завершается через `exit`.
5. Обработка исключений из пользовательского режима без паники ядра.
6. Потоки: свой стек ядра на поток, переключение по таймеру, `fxsave`, FS для TLS.
7. Отложенное отображение памяти, копирование из и в память программы, `futex`, часы, системные вызовы Go. **Проверка:** Go «hello world», затем горутины и `time.Sleep`.

## Подготовка (можно сделать до самого режима)

### GDT и TSS

- После TSS добавить сегмент данных пользователя, затем сегмент кода пользователя — именно в таком порядке, его требует `sysret`. Получатся индексы 5 и 6, селекторы `0x2b` и `0x33`, как `__USER_DS` и `__USER_CS` в Linux. База для регистра STAR — `0x20`; `x86_64::registers::model_specific::Star::write` проверяет раскладку.
- TSS сейчас неизменяемый (`lazy_static` в `src/gdt.rs`). Нужен изменяемый TSS и функция вроде `set_kernel_stack(rsp0)`: прерывание из пользовательского режима берёт стек ядра из `rsp0`, и при переключении потоков его надо менять.
- Отдельные стеки для double fault, NMI и machine check уже есть (`gdt::ist_stacks`). Page fault на отдельный стек **не** переносить: при отложенном отображении памяти он должен уметь вкладываться.

### Память

- **Освобождение страниц.** `RegionFrameAllocator` (`osel-core/src/memory.rs`) только выдаёт. Нужен список свободных страниц, связанный через отображение физической памяти, и `deallocate`; счётчики ссылок — только если понадобится копирование при записи. Без этого `munmap`, `madvise` и завершение программы текут.
- **Зануление.** Страницы для программ (`.bss`, анонимный `mmap`) должны быть нулевыми, иначе в программу утекут чужие данные. Нужен вариант `map_range` с занулением через отображение физической памяти.
- **Таблицы верхней половины.** При инициализации создать таблицы третьего уровня для всех записей 256..511. Тогда у всех адресных пространств общая и всегда актуальная часть ядра, и записи верхнего уровня достаточно скопировать.
- **Куча.** 1 МБ мало для потоков, адресных пространств и областей `fxsave`. Поднять `HEAP_SIZE` примерно до 16 МБ.
- **Адресное пространство.** Тип, который владеет своей таблицей верхнего уровня; `with_memory` работает с ним, а не с глобальной таблицей.

### Ramdisk

- `runner/` должен класть файл в образ через `DiskImageBuilder::set_ramdisk`, переменной окружения или флагом.
- Ядро находит его через `osel::boot_info()`: поля `ramdisk_addr` и `ramdisk_len`. Загрузчик отображает ramdisk в верхней половине и не отдаёт его страницы как свободные.
- Формат — архив (cpio или tar), чтобы тестовые программы и тетрис лежали в одном образе.

### SSE для программ

- CR0: `EM = 0`, `MP = 1`. CR4: `OSFXSR` и `OSXMMEXCPT`.
- Ядро собрано без SSE (`x86_64-unknown-none` — soft-float), поэтому сохранять регистры SSE нужно только при переключении между потоками программ, а не на каждом прерывании.
- Область `fxsave`/`fxrstor` — 512 байт, выравнивание 16, на каждый поток; начальное значение MXCSR — `0x1F80`.
- `CR4.OSXSAVE` не включать: тогда Go не использует AVX и не нужен `xsave`.

## Вход в ядро

- Данные на процессор (стек ядра, текущий поток) — через GS: `swapgs` на входе и выходе.
- `syscall` не переключает стек: заглушка сначала делает `swapgs`, берёт стек ядра из данных процессора и только потом пишет в память.
- SFMASK должен сбрасывать IF, DF, TF и AC.
- NMI или machine check, пришедшие сразу после `syscall`, до смены стека, окажутся на стеке программы — поэтому у них отдельные стеки (уже сделано).
- `sysretq` с неканоническим адресом в RCX на Intel даёт #GP в кольце 0, но ещё на стеке программы. Перед `sysretq` проверять RCX, при неканоническом — возврат через `iretq`.
- Обработчики `x86-interrupt` сохраняют не все регистры. Для переключения контекста нужны заглушки на ассемблере, которые кладут полный набор регистров в структуру вроде `TrapFrame` и вызывают один диспетчер на Rust; та же структура — у заглушки `syscall`.

## Программы

- **Загрузчик ELF:** сегменты по месту, права по флагам сегментов, `.bss` нулями.
- **Стартовый стек по System V ABI:** argc, argv, envp, auxv с `AT_PHDR`, `AT_PHENT`, `AT_PHNUM`, `AT_PAGESZ`, `AT_ENTRY`, `AT_RANDOM`. `AT_SYSINFO_EHDR` не передавать: без vDSO Go сам вызывает `clock_gettime` как системный вызов.
- **Исключения из пользовательского режима** (в CS кольцо 3) завершают поток или процесс, а не роняют ядро.
- **Память программы.** Go резервирует большие области без доступа и рассчитывает на отложенное выделение памяти. Нужен список областей адресного пространства, обработчик page fault для них и функции копирования из и в память программы с проверкой `< USER_END`.

## Потоки и время

- Свой стек ядра на поток (16–32 КБ) со страницей-охранником без отображения, по образцу `GuardedStack` в `src/gdt.rs`.
- Переключение по таймеру PIT 100 Гц (`TICK_HZ` в `src/interrupts.rs`) — его достаточно.
- FS — база TLS, её задаёт `arch_prctl(ARCH_SET_FS)`; сохранять при переключении потоков.
- `sched_getaffinity` отвечает «1 процессор», тогда GOMAXPROCS = 1.
- Часы для `clock_gettime`: TSC, откалиброванный по PIT. Очередь спящих потоков для `nanosleep`, тайм-аутов `futex` и `epoll`.
- `epoll` пока минимальный: сон с тайм-аутом и пробуждение. На регистрацию обычных файлов можно отвечать `EPERM` — Go перейдёт на блокирующее чтение.

## Системные вызовы для рантайма Go

Ориентир — около 30 вызовов. Неподдержанные возвращают `ENOSYS`.

| Группа | Вызовы |
|---|---|
| Ввод-вывод | `write`, `read`, `openat`, `close`, `fstat` |
| Память | `mmap`, `munmap`, `madvise`, `mprotect` |
| Потоки | `clone`, `futex`, `gettid`, `tgkill`, `sched_yield`, `sched_getaffinity`, `exit`, `exit_group` |
| Сигналы | `rt_sigaction`, `rt_sigprocmask`, `sigaltstack` |
| Время | `clock_gettime`, `nanosleep` |
| Прочее | `arch_prctl`, `getrandom`, `getpid`, `prlimit64`, `epoll_create1`, `epoll_ctl`, `epoll_pwait`, `pipe2`, `eventfd2` |

Когда появится первый вызов, заведём справочник `reference/syscalls.md` (номер, имя, статус, тест) и проверку в `cargo docs-check`, что каждый вызов из таблицы диспетчера в нём описан.

## Как тестировать

- Маленькие программы на ассемблере собираются при сборке и кладутся в ramdisk тестового ядра.
- Помощник вроде `run_user(elf) -> код_выхода`, чтобы тесты ядра проверяли код выхода и вывод в последовательный порт.
- Когда появится драйвер часов реального времени, перенести тесты форматов из Nikka (BCD и 12-часовой режим), см. [курс ШАДа](../nikka.md).
