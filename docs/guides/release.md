# Журнал изменений и выпуск версии

**Для кого:** для разработчиков и агентов, которые открывают PR или выпускают версию.

**Коротко:** каждый PR добавляет строку в раздел «Не выпущено» файла `CHANGELOG.md`. Выпуск версии — это переименование раздела в номер версии и тег `vX.Y.Z` на этот коммит. Документация всегда описывает `master`: версий документации нет, история изменений живёт только в журнале.

## Журнал изменений {#changelog}

`CHANGELOG.md` в корне репозитория ведётся по формату [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Сверху всегда раздел «Не выпущено», ниже — выпущенные версии от новых к старым.

Каждый PR, который меняет поведение системы или инструменты, добавляет в «Не выпущено» строку в одну из групп:

| Группа | Что сюда |
|---|---|
| Добавлено | новая возможность |
| Изменено | изменилось существующее поведение |
| Исправлено | исправлена ошибка |
| Удалено | возможность убрана |

Строка пишется для читателя, а не для автора: что изменилось для того, кто запускает или разрабатывает OSel. Правки только документации и тестов в журнал не попадают.

## Номера версий {#versions}

Используется [SemVer](https://semver.org/lang/ru/) с нулевой старшей цифрой: пока версия `0.x`, совместимость ничего не обещает.

- **Средняя цифра** растёт, когда закрыт этап плана: `0.1.0` — этап 1, `0.2.0` — этап 2.
- **Последняя цифра** растёт для исправлений между этапами: `0.1.1`.

Номер версии записан в `version` файла `Cargo.toml`. Ядро показывает версию и коммит при загрузке и на экране паники.

## Как выпустить версию {#release}

1. Убедитесь, что в `master` всё зелёное.
2. В `CHANGELOG.md` переименуйте «Не выпущено» в `## [X.Y.Z] — ГГГГ-ММ-ДД` и добавьте над ним новый пустой раздел «Не выпущено».
3. Поставьте `version = "X.Y.Z"` в `Cargo.toml`.
4. Откройте PR с этими правками, после мёржа поставьте тег на коммит мёржа:

   ```shell
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

5. Если закрыт этап, отметьте это в [плане](../roadmap.md).

## Почему без версий документации {#no-versioned-docs}

Документация описывает текущее состояние `master`. Старое поведение при необходимости смотрят в журнале изменений или в документации на нужном теге прямо в репозитории: `docs/` на теге `vX.Y.Z`.
