# Что пошло не так

**Для кого:** для разработчиков и агентов, у которых упал тест, CI или запуск.

**Коротко:** найдите в таблице текст сообщения или симптом. В каждой строке — причина и страница, где разобрано подробнее. Если сообщения нет в таблице, начните с [Отладки](debugging.md).

Сообщения вида `failed: …` печатает runner, а сообщения внутри паники печатает само ядро.

## Сообщения {#messages}

| Сообщение | Что значит | Что делать |
|---|---|---|
| ``deadlock on lock `X`: held since A, waiting at B`` | код, который держит блокировку `X` (место A), снова пытается её взять (место B), или блокировку не отпустили; на одном процессоре с выключенными прерываниями такое ожидание бесконечно | найдите оба места; часто это вложенный вызов `with_memory`, `with_allocator` или `println!` внутри обработчика, см. [Блокировки](../architecture/core/locking.md) |
| `the test leaked N heap bytes` | тест ядра выделил в куче память и не освободил её | освободите всё в конце теста, см. [Тесты](testing.md#kernel) |
| `the test leaked N frames` | тест ядра не вернул физическую страницу или таблицу страниц | верните страницы через `deallocate_frame`, пустые таблицы — через `clean_up_addr_range`, см. [Тесты](testing.md#kernel) |
| `frame … is not handed out: double free or a foreign frame` | страницу освободили дважды или освободили страницу, которую пул не выдавал | см. [пул страниц](../architecture/core/memory.md#frames) |
| `osel::init called twice` | `osel::init` вызвана второй раз; это запрещено, повторная инициализация испортила бы таблицы страниц | вызывайте один раз, после неё берите данные загрузчика из `osel::boot_info()` |
| `failed: qemu exit code Some(35)` | тестовое ядро сообщило о провале: выше в выводе есть `[failed]` и текст ошибки | читайте текст над этой строкой |
| `failed: qemu exit code Some(0)` или `Some(1)` | QEMU завершился, но не через устройство выхода: обычно тройной сбой (с `-no-reboot` перезагрузка превращается в выход) | см. [Перезагрузка без экрана паники](debugging.md#triple-fault) |
| `failed: N of M tests reported [ok]` | тестовое ядро завершилось успешно, но отчитались не все объявленные тесты (или лишние) | кто-то вызвал `exit_qemu` раньше времени или вывод теста смешался с другим выводом в одной строке |
| `failed: no test reported [ok]` | тестовое ядро завершилось успешно, ничего не напечатав | тело теста не дошло до проверки, либо `harness = false` тест забыл вызвать `pass()` |
| `failed: timed out after 60s` | тестовое ядро зависло, и runner его остановил (число — значение `OSEL_TIMEOUT`, по умолчанию 60) | см. последний тест в выводе; если CI просто медленный, временно поднимите `OSEL_TIMEOUT` |
| ``failed: `<текст>` not printed within 60s`` | запуск с `OSEL_EXPECT` не дождался строки: ядро зависло или упало, не напечатав её в порт | посмотрите вывод выше; проверьте, что текст печатается через `serial_println!`, а не только на экран |
| ``failed: kernel stopped with … before printing `<текст>` `` | при запуске с `OSEL_EXPECT` QEMU завершился раньше, чем появилась строка: обычно паника или тройной сбой | посмотрите вывод выше, см. [Отладка](debugging.md) |
| ``unknown OSEL_BOOT value `x`, expected `uefi` or `bios` `` | неверное значение `OSEL_BOOT`, runner вышел до запуска QEMU | допустимы только `uefi` и `bios`, см. [Runner](../reference/runner.md) |
| ``OSEL_TIMEOUT must be a positive number of seconds, got `x` `` | неверное значение `OSEL_TIMEOUT`, runner вышел до запуска QEMU | укажите целое число секунд больше нуля |
| `failed to fetch OVMF firmware` | runner не смог скачать прошивку UEFI для QEMU | нужен интернет при первом запуске; прошивка сохраняется в `runner/.ovmf` (место меняет `OSEL_OVMF_DIR`), см. [Runner](../reference/runner.md) |
| `warning: test arguments are not supported and ignored` | вы запустили `cargo test -- <фильтр>` | см. [Runner](../reference/runner.md); одно тестовое ядро запускается через `cargo test --test <имя>` |

## Симптомы {#symptoms}

| Симптом | Причина | Где подробнее |
|---|---|---|
| В CI падает `test_timer_frequency_against_rtc` с `N ticks per second, expected 100` | QEMU в CI работает без аппаратной виртуализации и на загруженной машине пропускает тики таймера; тест допускает 25–400 тиков в секунду | `src/interrupts.rs`, тест `test_timer_frequency_against_rtc`; [Прерывания](../architecture/core/interrupts.md) |
| Тест проходит в UEFI и падает в BIOS или наоборот | прошивки по-разному настраивают память и устройства | запускайте `OSEL_BOOT=bios cargo test` |
| Сборка ломается сразу после обновления nightly | новая версия компилятора изменила нестабильные возможности | откатите `rust-toolchain.toml`, см. [Тулчейн и CI](toolchain-and-ci.md) |
| Еженедельная задача CI `latest nightly` красная, остальное зелёное | на свежем nightly что-то сломалось, на закреплённом всё работает | ничего срочного; разберитесь до следующего обновления тулчейна |
| На ноутбуке OSel загрузился, но клавиатура не печатает | внешняя USB-клавиатура без эмуляции legacy USB в BIOS; встроенная клавиатура ноутбука обычно подключена как PS/2 и работает | [Клавиатура](../architecture/drivers/keyboard.md), страницы машин в справочнике |
| Ноутбук не видит флешку в меню загрузки | включён Fast BIOS Mode или Secure Boot, либо образ не для того режима загрузки | [Запуск с флешки](../start/usb.md) |
| Красный экран на ноутбуке | ядро упало | [Красный экран](../start/crash-report.md) |
| Чёрный экран или перезагрузка без экрана паники | тройной сбой или сбой до инициализации экрана | [Отладка](debugging.md#triple-fault) |
