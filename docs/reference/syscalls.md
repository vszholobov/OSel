# Системные вызовы

**Для кого:** для тех, кто пишет программу для OSel или добавляет системный вызов.

**Коротко:** OSel реализует системные вызовы Linux x86_64 с теми же номерами и соглашением: номер в RAX, аргументы в RDI, RSI, RDX, R10, R8, R9, результат или `-errno` в RAX, RCX и R11 портятся, остальные регистры сохраняются. Номер — младшие 32 бита RAX как знаковое число. Неизвестный номер — `ENOSYS`. Как устроен вход — в [пользовательском режиме](../architecture/core/user-mode.md#syscall). Таблицу сверяет с `SYSCALLS` в `osel-core/src/syscall.rs` тест `cargo docs-check`.

## Вызовы {#calls}

| Номер | Вызов | Аргументы | Что делает OSel | Ошибки |
|---|---|---|---|---|
| 0 | `read` | `fd`, `buf`, `count` | читает не больше 64 КБ за вызов; файл — со смещения описания, `/dev/null` — 0, терминал ждёт первой клавиши, а с `O_NONBLOCK` отвечает `EAGAIN` | `EBADF` без права чтения; `EFAULT` до чтения, если буфер не принадлежит программе; `EISDIR` у каталога; `EINTR`, если процесс убили, пока чтение ждало |
| 1 | `write` | `fd`, `buf`, `count` | терминал — текст на экран и в последовательный порт, символ UTF-8, разрезанный между двумя `write`, печатается целым, сломанные байты — U+FFFD; `/dev/null` — принимает всё. Возвращает `count` | `EBADF` без права записи; `EFAULT`, если хоть один байт буфера не принадлежит программе, — тогда не пишется ничего |
| 3 | `close` | `fd` | закрывает дескриптор; описание живёт, пока на него есть другие | `EBADF` |
| 5 | `fstat` | `fd`, `statbuf` | `struct stat` x86_64, см. [открытые файлы](../architecture/core/fs.md#open-files) | `EBADF`, `EFAULT` |
| 9 | `mmap` | `addr`, `len`, `prot`, `flags`, `fd`, `offset` | только анонимная память (`MAP_ANONYMOUS`; `MAP_SHARED` — как `MAP_PRIVATE`, `fork` нет). Страниц сразу нет, они появляются при первом обращении, см. [память программ](../architecture/core/memory.md#areas). Без `MAP_FIXED` берёт свободную подсказку `addr` (округлённую вниз) или самое высокое свободное место ниже `MMAP_TOP`; `MAP_FIXED` заменяет всё, что было в диапазоне, `MAP_FIXED_NOREPLACE` — только на свободном месте | `EINVAL` для `len` 0, невыровненного `offset`, неизвестных битов `prot` (Linux их не проверяет), без `MAP_PRIVATE` или `MAP_SHARED`; `EBADF`, а с открытым `fd` — `ENODEV` для файла; `ENOMEM`, если места нет или диапазон выходит за нижнюю половину; `EPERM` для `MAP_FIXED` ниже `0x10000`; `EEXIST` |
| 10 | `mprotect` | `addr`, `len`, `prot` | меняет права всех страниц диапазона; `len` 0 — ничего | `EINVAL` для невыровненного `addr` и неизвестных битов `prot`; `ENOMEM`, если часть диапазона не отображена, — тогда не меняется ничего |
| 11 | `munmap` | `addr`, `len` | убирает области и освобождает страницы; пустой диапазон — не ошибка | `EINVAL` для невыровненного `addr`, `len` 0 и диапазона за нижней половиной |
| 35 | `nanosleep` | `req`, `rem` | спит на время `timespec` из `req`, блокируя поток; при убийстве процесса пишет остаток в `rem` и `EINTR`. Шаг времени — один тик таймера (10 мс) | `EINVAL` для отрицательного или слишком большого `tv_nsec`; `EFAULT`; `EINTR` |
| 56 | `clone` | `flags`, `child_stack`, … | создаёт ещё один поток того же процесса (общие память и дескрипторы); ребёнок получает `rax = 0` и свой стек, родитель — tid ребёнка. Только набор флагов потока Go (`VM\|FS\|FILES\|SIGHAND\|THREAD\|SYSVSEM`) | `EINVAL` для других флагов, нулевого или слишком большого `child_stack`, `ENOMEM` без стека ядра |
| 24 | `sched_yield` | — | отдаёт процессор следующему готовому потоку | — |
| 28 | `madvise` | `addr`, `len`, `advice` | `MADV_DONTNEED` и `MADV_FREE` отдают страницы: следующее чтение даёт нули; другие советы Linux ничего не делают; `len` 0 — ничего | `EINVAL` для невыровненного `addr`, неизвестного совета и `MADV_REMOVE` (только для общей памяти); `ENOMEM`, если часть диапазона не отображена (отображённая часть обработана) |
| 202 | `futex` | `uaddr`, `op`, `val`, `timeout` | `FUTEX_WAIT` спит, пока слово по `uaddr` равно `val` (с необязательным относительным тайм-аутом по монотонным часам); `FUTEX_WAKE` будит до `val` ждущих и возвращает их число. Только эти две операции, с флагом `FUTEX_PRIVATE_FLAG` или без | `EAGAIN`, если значение уже другое; `ETIMEDOUT`; `EINTR`; `EFAULT`; `ENOSYS` для других операций |
| 228 | `clock_gettime` | `clock_id`, `timespec` | пишет время: `CLOCK_MONOTONIC` — наносекунды с загрузки, `CLOCK_REALTIME` — с эпохи Unix (база из CMOS при загрузке); варианты `_COARSE`, `_RAW`, `BOOTTIME` — те же | `EINVAL` для неизвестных часов; `EFAULT` |
| 186 | `gettid` | — | номер текущего потока | — |
| 39 | `getpid` | — | возвращает 1: номеров процессов пока нет | — |
| 60 | `exit` | `status` | завершает программу, код выхода — младшие 8 бит `status` | — |
| 72 | `fcntl` | `fd`, `cmd`, `arg` | `F_DUPFD`, `F_DUPFD_CLOEXEC`, `F_GETFD`, `F_SETFD`, `F_GETFL` (с `O_LARGEFILE`, как в Linux), `F_SETFL` (меняет только `O_APPEND` и `O_NONBLOCK`) | `EBADF` раньше всего; `EINVAL` для других команд и плохой нижней границы; `EMFILE` |
| 231 | `exit_group` | `status` | то же, что `exit`: потоков пока нет | — |
| 257 | `openat` | `dirfd`, `path`, `flags`, `mode` | открывает файл, каталог или устройство `/dev`; относительный путь — от `dirfd` или, при `AT_FDCWD`, от `/`. Флаги — в порядке Linux, см. [открытые файлы](../architecture/core/fs.md#open-files) | `ENOENT`, `ENOTDIR`, `EISDIR`, `EROFS`, `EEXIST`, `EMFILE`, `EBADF` для `dirfd`, `EFAULT`, `ENAMETOOLONG` |
| 262 | `newfstatat` | `dirfd`, `path`, `statbuf`, `flags` | `stat` по пути, с `AT_EMPTY_PATH` и пустым путём — сам `dirfd`; символьных ссылок нет, `AT_SYMLINK_NOFOLLOW` ничего не меняет | как у `openat` и `fstat` |

Дескрипторы (`fd`, `dirfd`) и совет `madvise` — младшие 32 бита регистра как знаковое число, как `int` в Linux. Права `prot` с битами выше 32 — `EINVAL`.

Новый вызов — номер и имя в `SYSCALLS`, ветка в `dispatch` (`src/syscall.rs`) и строка в этой таблице. Адреса от программы — только через `copy_from_user` и `copy_to_user`, см. [пользовательский режим](../architecture/core/user-mode.md#user-mem).
