# Runner

**Для кого:** все, кто запускает ядро или тесты.

**Коротко:** runner (`runner/`) — инструмент на хост-машине, который cargo вызывает вместо запуска ядра. Он собирает образ диска из ELF ядра и запускает QEMU. Поведение настраивается переменными `OSEL_*`. Как устроены тесты — в [отдельной странице](../architecture/testing.md).

## Как вызывается {#invocation}

`.cargo/config.toml` задаёт для таргета `x86_64-unknown-none` раннер `runner/run.sh`. Скрипт собирает и запускает крейт runner под хост-машину (`cargo run` с `--target host-tuple`) и передаёт ему путь к ELF ядра и аргументы QEMU. Путь к скрипту cargo считает от корня репозитория, поэтому `cargo run` работает из любой подпапки.

## Переменные окружения {#env}

| Переменная | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `OSEL_BOOT` | `uefi`, `bios` | `uefi` | какой образ собрать и как загрузить. Пустое значение — то же, что не задано, другое значение — ошибка |
| `OSEL_EXPECT` | любой текст | не задано | режим смоук-теста: загрузить настоящее ядро без окна и завершиться успехом, как только строка с этим текстом появится в последовательном порту |
| `OSEL_TIMEOUT` | целое число секунд больше 0 | 60 | предел для тестовых ядер и режима `OSEL_EXPECT` |
| `OSEL_OVMF_DIR` | путь к папке | папка .ovmf внутри runner | куда скачать и где хранить прошивку UEFI для QEMU |

## Режимы {#modes}

Режим выбирается автоматически (`Mode` в `runner/src/main.rs`):

| Режим | Когда | Что добавляется к QEMU | Чем заканчивается |
|---|---|---|---|
| Run | обычный `cargo run` | ничего, открывается окно | кодом выхода QEMU; если QEMU убит сигналом, кодом 128 + номер сигнала |
| Test | имя ELF оканчивается на `-<16 шестнадцатеричных цифр>`, так cargo называет тестовые бинарники | `isa-debug-exit` на порту `0xf4`, без окна, 128 МБ памяти, ввод отключён от терминала | успехом, только если выполнены критерии ниже; образ диска удаляется |
| Expect | не тест и задана `OSEL_EXPECT` | без окна, ввод отключён от терминала | успехом, как только текст найден; QEMU останавливается |

Во всех режимах QEMU запускается с `-serial stdio -no-reboot`. Аргументы после `--` у `cargo run` передаются QEMU; у тестовых ядер они игнорируются с предупреждением.

## Коды выхода тестового ядра {#exit-codes}

| Ядро вызвало | Значение в порт `0xf4` | Код выхода QEMU |
|---|---|---|
| `exit_qemu(QemuExitCode::Success)` | `0x10` | 33 |
| `exit_qemu(QemuExitCode::Failed)` | `0x11` | 35 |
| тройной сбой и перезагрузка при `-no-reboot` | — | 0 |

## Критерии прохождения теста {#pass}

1. QEMU завершился до таймаута, иначе «timed out after N s».
2. Код выхода 33, иначе «qemu exit code …».
3. Если в выводе была строка `Running N tests`, строк, оканчивающихся на `[ok]`, ровно `N`.
4. Если такой строки не было, есть хотя бы одна строка `[ok]`.

Вывод ядра пересылается в терминал после фильтра: вырезаются управляющие последовательности терминала и строки менеджера загрузки OVMF (`BdsDxe:`), пустые строки самого ядра сохраняются.

## Файлы {#files}

| Что | Где |
|---|---|
| Образ диска | рядом с ELF: `<имя>.uefi.img` или `<имя>.bios.img`; для настоящего ядра — target/x86_64-unknown-none/debug/OSel.uefi.img |
| Прошивка UEFI | папка .ovmf внутри runner, скачивается при первом запуске под UEFI (крейт `ovmf-prebuilt`), в git не попадает |
| Уровень логов загрузчика | `Warn`: шаги загрузки не печатаются, только проблемы |

## Где в коде {#code}

- `runner/run.sh` — обёртка для cargo.
- `runner/src/main.rs` — `parse_boot`, `parse_timeout`, `is_test_binary`, `image_path`, `create_disk_image`, `ovmf_firmware`, `forward_serial_output`, `test_outcome`, `expect_outcome`, `wait_with_timeout`.
