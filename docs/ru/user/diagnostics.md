# Диагностика

**Для кого:** пользователь, который проверяет сеть или передаёт сведения о сбое.

**Коротко:** `diag` собирает общий отчёт. `ping gateway` проверяет связь с роутером после DHCP; `ping IP` проверяет указанный IPv4. Для Acer есть `wifi probe` и снимок результата `wifi regs`; добавлены команды WPA2, аппаратная проверка подключения ещё требуется.

## Команды {#commands}

| Команда | Что показывает или делает |
|---|---|
| `diag` | версию, коммит, время работы, PIT, память, клавиатуру, PCI сетевых карт, Ethernet, DHCP, маршрут, DNS, TCP и состояние Wi-Fi |
| `pci` | PCI ID, subsystem, ревизию, класс, BAR0 и PCI command |
| `net` | карту, линию, адреса, сокеты, принятые, отправленные и отброшенные кадры |
| `net ip` | MAC, адрес/маску, получение DHCP и число конфигураций |
| `net route` | подключённую подсеть и шлюз по умолчанию |
| `net dns` | адреса DNS-серверов из DHCP |
| `net tcp` | соединения, конечные адреса, состояние, очереди и ошибки |
| `net dhcp` | начинает DHCP заново; через несколько секунд проверьте `net ip` |
| `ping gateway [число]` | ICMP Echo до шлюза из DHCP |
| `ping IP [число]` | ICMP Echo, задержку и потери; по умолчанию 4 пакета, от 1 до 10 |
| `tcpcheck IP порт` | проверяет соединение с TCP-портом за 3 секунды; различает отказ и тайм-аут |
| `nslookup имя` | IPv4-адреса из DNS, максимум 5 секунд ожидания |
| `wifi status` | PCI-карту QCA6174, последний этап проверки и ошибку |
| `wifi fw` | версию встроенной прошивки, API/WMI/HTT, OTP и точное совпадение платы |
| `wifi probe` | проверяет Acer-карту до ответа встроенного загрузчика BMI; ещё не запускает прошивку и не подключается к сети |
| `wifi load` | повторяет ROM-проверку, загружает калибровку/прошивку и ждёт HTC/WMI ready; после проверки карта останавливается, подключения ещё нет |
| `wifi scan` | загружает прошивку и объединяет три пассивных прохода по 2,4 ГГц и выбранным каналам 5 ГГц; показывает до 20 AP: SSID, BSSID, частоту, сигнал и совместимость WPA2; после проверки карта останавливается |
| `wifi results` | сохранённые результаты последнего успешного сканирования, без доступа к карте |
| `wifi connect N` | подключение к WPA2 AP с номером N из wifi results; пароль вводится отдельно без эха; затем DHCP |
| `wifi disconnect` | останавливает Wi-Fi, очищает сетевую конфигурацию и прерывает соединения |
| `wifi regs` | последние 22 сохранённых этапа и значения проверки; регистры повторно не читает |
| `kbd` | инициализацию PS/2, IRQ и счётчики ввода |

`ping` делает не более одного запроса в секунду, ждёт ответ до 1 секунды и останавливается по Ctrl+C. Тайм-аут означает отсутствие ответа ICMP: сервер тетриса может работать при запрещённом ICMP. `ENETUNREACH` означает отсутствие карты, линии или DHCP-адреса. Шлюз должен быть получен через DHCP; адрес `10.0.2.2` подходит только гостю QEMU. Multicast, loopback и broadcast для `ping` отвергаются.

`nslookup` работает в оболочке. Программы Go пока используют числовой IPv4 или `/etc/hosts`: Linux UDP-сокеты для их DNS-резолвера ещё не реализованы. Возвращённый `nslookup` адрес можно указать игре вручную.

## Передать отчёт {#report}

1. После загрузки выполните `clear`, затем `diag`. Сохраните вывод COM1 или сфотографируйте экран с версией и коммитом.
2. Для Wi-Fi на [Acer](hardware/acer-nitro.md#wifi) выполните `wifi probe`, затем `clear` и `wifi regs`; сохраните ещё этот экран. Ошибка и этап полезны даже при неудаче.
3. Для проводной сети после DHCP выполните `ping gateway 4`, затем `ping IP_сервера 4`. Проверьте `tcpcheck IP_сервера 8080`. При проблеме игры добавьте текст ошибки и адрес сервера.

`wifi load` имеет общий предел 120 секунд после ROM-проверки и отменяется по Ctrl+C. Этапы и число загруженных байтов видны на экране. После `firmware check passed; target stopped` запуск прошивки подтверждён по HTC/WMI; затем можно запустить `wifi scan`, выбрать сеть через `wifi connect N` и проверить `net ip` и `ping gateway`. Подключение на Acer ещё не подтверждено. При неудаче сохраните `wifi regs`.

В отчёт не входят пароли и ключи Wi-Fi. Полный вывод автоматически дублируется в COM1. Если ноутбук завис именно на `wifi probe`, сохраните последнюю строку: этапы печатаются по мере выполнения на экране и в COM1. Проверка не запускается автоматически при загрузке; при повторной загрузке оболочка остаётся доступной.

## Подключение Wi-Fi {#connect}

В новом образе выполните `wifi scan`, затем `wifi connect N`, где N — номер сети с пометкой WPA2. Пароль вводится на ноутбуке без эха и не нужен в отчёте. Требуются видимый SSID, WPA2-Personal/CCMP и 2,4 ГГц, канал 1–11. WPA3-only, Enterprise, обязательный PMF и скрытый SSID не поддерживаются. Начальная мощность 0 dBm: проверяйте рядом с роутером.

Список обнаружения шире возможностей подключения: поиск охватывает каналы 1–13 и выбранные каналы 5 ГГц в пределах платы; подключение работает только на 1–11. DFS и 6 ГГц не сканируются. Поэтому близкая точка телефона может отсутствовать; её диапазон нельзя определить по имени модели телефона.

Под сетью выводится `Cannot connect:` с точной причиной. `group cipher requires CCMP/AES` означает, что групповое шифрование AP не подходит, даже если пароль верный и unicast предлагает AES. `no WPA2 RSN` означает отсутствие подходящего WPA2-описания; WPA1/WEP не реализованы. PSK и обязательный PMF проверяются отдельно. Для совместимой конфигурации роутера нужны WPA2-Personal и AES/CCMP для group и pairwise; обязательный PMF не поддерживается. Старый вывод `UNSUPPORTED` без причины не позволяет определить конкретный режим Rostel-6.

Если результат пустой или непостоянный, выполните `clear`, `wifi regs`: нужны `passive scan channel visits`, `management frames`, `bad WMI frames`, `bad beacons` и `networks`, а также commit из `diag`. Три прохода объединяются в одной команде; `No saved networks` не подтверждает отсутствие AP. Увеличенная очередь приёма и повторные проходы пока не подтверждены на Acer.

После `WiFi DHCP ready` выполните `net ip`, `ping gateway 4`, `tcpcheck SERVER_IP 8080`, затем запустите [тетрис](network.md). При ошибке — `clear`, `wifi regs`, `wifi status` и `diag`; нужны последний этап, errno и commit. При тайм-ауте DHCP worker остаётся активен; после исправления DHCP можно повторить `net dhcp`. Для повторного подключения сначала `wifi disconnect`.

При ETIMEDOUT во время подключения сохраните `wifi regs`. `STA HTT TX completion wait` означает отсутствие завершения передачи; `STA authentication response wait` — TX завершён, но подходящий ответ AP не принят. Оба этапа идут до проверки пароля WPA2. Отчёт содержит TX ID, completion status и счётчики приёма, но не пароль.

## Что подтверждено {#limits}

В QEMU проверяются команды, отсутствие QCA6174, настоящий ICMP, автомат WPA2, владение DMA, смена адаптера и очистка при потере связи. QEMU не эмулирует QCA6174. На Acer подтверждены HTT 3.87 и список из 18 AP с Galaxy S23. Повторный поиск нестабилен; WPA2, DHCP и игра по Wi-Fi требуют отдельной аппаратной проверки; текущий статус — в [описании драйвера](../developer/architecture/drivers/wifi.md#abi-audit).
