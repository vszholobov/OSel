# Запуск с флешки

Язык: [Русский](usb.md) · [English](../../en/user/usb.md)

**Для кого:** для тех, кто хочет запустить OSel на настоящем компьютере.

**Коротко:** скачайте готовый образ из GitHub Releases, проверьте его контрольную сумму, запишите на флешку целиком и загрузитесь с неё через меню загрузки компьютера. Rust, Go и сборка проекта не нужны. Диски компьютера OSel не трогает, а чтобы вернуть обычную систему, достаточно вынуть флешку. Самое опасное — выбрать при записи не тот диск, поэтому проверяйте его дважды.

{% note alert %}

Запись образа стирает **весь** выбранный диск. Если по ошибке указать внутренний диск вместо флешки, данные на нём пропадут. Скрипта, который это проверяет, пока нет: выбор диска целиком на вас.

{% endnote %}

## 0. Подготовьте компьютер {#prepare}

Сделайте это **до** записи флешки и до любых изменений в настройках BIOS:

- **Ноутбук с Windows и шифрованием BitLocker.** Сохраните ключ восстановления: после выключения Secure Boot Windows попросит его при следующем запуске, и без ключа в неё не попасть. Где найти ключ — на странице [Acer Nitro](hardware/acer-nitro.md).
- **Загрузка через UEFI.** Выключите Secure Boot: загрузчик OSel не подписан. Как это сделать на конкретной машине — в справочнике: [Acer Nitro](hardware/acer-nitro.md).
- **Samsung.** Выключите Fast BIOS Mode, иначе ноутбук не видит флешку: [Samsung NP530U4B](hardware/samsung-np530u4b.md).

Запомните, что вы поменяли: после экспериментов эти настройки стоит вернуть, см. [Как вернуть обычную систему](#recovery).

## 1. Скачайте образ и проверьте сумму {#image}

Какой образ нужен, зависит от того, как загружается компьютер:

| Компьютер | Образ |
|---|---|
| Загружается через UEFI (большинство компьютеров с Windows 8 и новее) | `OSel.uefi.img` |
| Загружается через старый BIOS или в режиме совместимости (CSM), в том числе Samsung 2012–2013 годов | `OSel.bios.img` |

{% note alert %}

Ноутбуки Samsung 2012–2013 годов, например NP530U4B, могли перестать включаться после записи настроек в режиме UEFI. Для них используйте только `OSel.bios.img` и режим BIOS (CSM). Подробнее — на странице [Samsung NP530U4B](hardware/samsung-np530u4b.md).

{% endnote %}

Откройте [GitHub Releases](https://github.com/vszholobov/OSel/releases) и выберите выпуск, в **Assets** которого есть `OSel.uefi.img`, `OSel.bios.img` и `SHA256SUMS`. У старых выпусков готовых образов может не быть. Скачайте нужный `.img` и `SHA256SUMS` из одного выпуска в одну папку. Архивы **Source code** для записи флешки не нужны.

Образы не сжаты, распаковывать их не нужно. Внутри уже есть оболочка, тетрис, внешняя `clear` и лицензия шрифта.

В этой папке посчитайте SHA-256 скачанного файла (для BIOS замените имя на `OSel.bios.img`):

{% list tabs %}

- macOS

  ```shell
  shasum -a 256 OSel.uefi.img
  ```

- Linux

  ```shell
  sha256sum OSel.uefi.img
  ```

- Windows (PowerShell)

  ```powershell
  Get-FileHash .\OSel.uefi.img -Algorithm SHA256
  ```

{% endlist %}

Сравните полученные 64 символа со строкой для этого файла в `SHA256SUMS`; регистр букв не важен. При несовпадении скачайте образ заново и не записывайте его. Если скачаны оба образа, на macOS можно проверить их вместе командой `shasum -a 256 -c SHA256SUMS`, на Linux — `sha256sum -c SHA256SUMS`: у обоих файлов должно быть `OK`.

### Дополнительно: самостоятельная сборка {#build-image}

Если нужен образ из исходников, установите инструменты из [быстрого старта](../developer/guides/quickstart.md#requirements). В папке OSel выполните одну из команд. QEMU запускается без окна и закрывается сам, как только ядро загрузилось:

```shell
OSEL_EXPECT="OSel ready to go!" cargo run --release --locked                 # UEFI
OSEL_BOOT=bios OSEL_EXPECT="OSel ready to go!" cargo run --release --locked  # BIOS
```

Образы появляются в `target/x86_64-unknown-none/release/`. Скопируйте нужный `.img` в папку, из которой будете выполнять команды записи ниже. Чтобы в нём был тетрис, нужны Go и инициализированный подмодуль, как в быстром старте.

## 2. Запишите образ на флешку {#write}

Подойдёт флешка любого размера от 64 МБ. Всё, что на ней есть, будет стёрто.

{% list tabs %}

- macOS

  1. Посмотрите список дисков, вставьте флешку и посмотрите ещё раз. Новый диск в списке — это флешка:

     ```shell
     diskutil list
     ```

     Флешка выглядит как `/dev/disk4 (external, physical)` с размером вашей флешки. Диск с пометкой `internal` — это диск компьютера, его выбирать нельзя. Номер `4` здесь для примера, в командах ниже подставьте свой.

  2. Отмонтируйте флешку (номер подставьте свой):

     ```shell
     diskutil unmountDisk /dev/disk4
     ```

  3. Запишите образ. Обратите внимание на `r` в `/dev/rdisk4`: так запись идёт в разы быстрее.

     ```shell
     sudo dd if=OSel.uefi.img of=/dev/rdisk4 bs=4m
     ```

  4. После записи macOS может показать окно «Диск не читается этим компьютером». Нажмите «Игнорировать» или «Извлечь», **не** «Инициализировать»: инициализация сотрёт записанный образ.
  5. Извлеките флешку: `diskutil eject /dev/disk4`.

- Linux

  1. Выполните `lsblk -d -o NAME,SIZE,MODEL,TRAN`, вставьте флешку и выполните ещё раз. Новый диск в списке — это флешка, у неё в столбце `TRAN` стоит `usb`. Её имя вида `sdb` подставьте вместо `sdX` ниже.
  2. Если система её смонтировала, отмонтируйте все разделы: `sudo umount /dev/sdX*`.
  3. Запишите образ на весь диск, а не на раздел (`/dev/sdX`, а не `/dev/sdX1`):

     ```shell
     sudo dd if=OSel.uefi.img of=/dev/sdX bs=4M conv=fsync status=progress
     ```

- Windows

  Используйте [Rufus](https://rufus.ie) или [balenaEtcher](https://etcher.balena.io): выберите файл образа и флешку. Эти программы показывают только съёмные диски, поэтому ошибиться с выбором труднее. В Rufus выбирайте режим записи образа целиком (DD).

{% endlist %}

## 3. Загрузитесь с флешки {#boot}

1. Вставьте флешку в выключенный компьютер.
2. Включите его и нажимайте клавишу меню загрузки (Boot Menu). Она зависит от производителя:

   | Производитель | Клавиша |
   |---|---|
   | Lenovo, Dell, Acer | F12 |
   | Samsung | F10 |
   | HP | F9 или Esc |
   | ASUS | Esc или F8 |
   | MSI | F11 |

3. Выберите флешку. Если её нет в списке, проверьте настройки из [шага 0](#prepare).

## Как проверить {#check}

На экране появятся строки `OSel X.Y.Z (commit …) woke up!`, `OSel ready to go!` и приглашение `osel>`. Версия и коммит должны совпадать с описанием скачанного релиза. Введите `help` или `tetris`; из игры можно вернуться по `x`.

Если клавиатура не работает, нажмите несколько букв, подождите 3–5 секунд и сфотографируйте экран с `PS/2 init` и строкой `KBD`. Скажите, меняется ли число `t`, или пришлите короткое видео. Диагностика появляется сама, команда для неё не нужна. Если ввод работает, подробности можно повторно вывести командой `kbd`. Расшифровка — в [диагностике клавиатуры](../developer/architecture/drivers/keyboard.md#diagnostics).

## Как вернуть обычную систему {#recovery}

Выключите компьютер, удерживая кнопку питания 5–10 секунд, выньте флешку и включите снова. OSel не умеет записывать на диски компьютера, поэтому установленная система не меняется.

Когда эксперименты закончены:

- **Верните настройки BIOS**, которые меняли на [шаге 0](#prepare): включите Secure Boot и Fast BIOS Mode обратно. После включения Secure Boot Windows с BitLocker может ещё раз спросить ключ восстановления.
- **Верните флешку к обычному использованию.** После записи образа операционная система видит её как нечитаемую или маленькую. Отформатируйте её целиком: на macOS — в «Дисковой утилите», выбрав саму флешку (а не раздел) и нажав «Стереть»; на Windows — в «Управлении дисками» или той же программой Rufus; на Linux — например, в GNOME Disks.

## Частые ошибки {#errors}

| Что видно | Что делать |
|---|---|
| Флешки нет в меню загрузки | выключите Fast BIOS Mode (Samsung) или Secure Boot (UEFI), проверьте, что образ подходит к режиму загрузки |
| Чёрный экран, ничего не происходит | попробуйте образ для другого режима: `OSel.bios.img` вместо `OSel.uefi.img` или наоборот |
| Красный экран «OSel crashed :(» | ядро упало, см. [Красный экран](crash-report.md) |
| Текст на экране есть, но клавиатура не печатает | внешняя USB-клавиатура работает только с эмуляцией USB legacy в BIOS; попробуйте встроенную клавиатуру ноутбука |
