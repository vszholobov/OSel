# Последовательный порт

**Для кого:** разработчик и агент, которые пишут в последовательный порт или отлаживают вывод тестов.

**Коротко:** макросы `serial_print!` и `serial_println!` пишут в порт COM1. В QEMU этот вывод попадает в терминал, через него тесты сообщают результаты. Порт проверяется при первом использовании, и если его нет (как на большинстве ноутбуков), вывод просто пропускается. Для паники есть аварийный вывод без блокировок.

## Как работает {#how}

- `port()` (`src/drivers/cereal.rs`) берёт блокировку `SERIAL1`. При первом вызове он проверяет порт по адресу `0x3F8` через `Uart16550Tty::new_port`. Если проверка не прошла, в `SERIAL1` остаётся `None`, и вывод пропускается.
- `serial_print!` и `serial_println!` вызывают `_print`, ошибки записи игнорируются.
- При загрузке настоящего ядра `src/main.rs` дублирует в порт баннер с версией и коммитом; проверка готовых релизных образов сверяет его перед запуском команд оболочки.
- Пользовательский терминал использует `write_terminal`: отправляет сырые байты порциями по готовности FIFO, без преобразования UTF-8 и CR/LF диагностическим форматтером. `SERIAL1` отпускается перед ожиданием готовности; при обычной записи прерывания включены и поток может быть вытеснен. Вывод остаётся синхронным, при заполненном FIFO повторяется неблокирующая проверка готовности.
- `receive` вычитывает только уже полученные байты. Таймер вызывает `tty::poll_serial` каждые 10 мс: за тик вычитывается не более 64 байт в заранее выделенный буфер, затем просыпаются потоки, читающие терминал. IRQ4 остаётся закрытым: для ввода игры достаточно задержки в один тик, а отдельный обработчик UART и его подтверждение пока не нужны. Это ограничивает скорость ввода; переполненный буфер теряет новые байты.
- `emergency_print` пишет прямо в регистры порта, без блокировок и без проверки. Ожидание готовности передатчика ограничено, поэтому при отсутствии порта он не виснет. Им пользуются вложенная паника и `test_panic_handler`.

## Где в коде {#code}

- `src/drivers/cereal.rs` — `SERIAL1`, `port`, `_print`, `emergency_print`, макросы `serial_print!` и `serial_println!`.

## Инварианты {#invariants}

- Отсутствие порта — не ошибка: ядро должно работать на машине без COM1.
- Путь паники не зависит от блокировки `SERIAL1`: экран паники снимает её силой, вложенная паника пишет через `emergency_print`.

## Блокировки и контекст прерываний {#locks}

`SERIAL1` — `IrqSpinlock`. Обработчик таймера читает порт без ожидания и выделения памяти; обработчики прерываний в порт не пишут.

## Грабли {#pitfalls}

- **Порт не на `lazy_static`.** Раньше порт инициализировался через `lazy_static`, и паника внутри проверки оставляла его наполовину инициализированным. Любое следующее обращение, включая путь паники, висело навсегда. Теперь проверка делается один раз флагом `PROBED`, а неудача даёт `None`.
- **На ноутбуке вывода в порт нет,** единственный способ увидеть ошибку — экран.

## Тесты {#tests}

- `src/drivers/cereal.rs` — порт есть в QEMU, макрос работает внутри выражения.
- `tests/panic_while_printing.rs` — паника при взятой `SERIAL1`.
- `tests/nested_panic.rs` — аварийный вывод.
