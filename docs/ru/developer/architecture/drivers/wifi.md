# Wi-Fi QCA6174

**Для кого:** разработчик аппаратного драйвера и запуска прошивки.

**Коротко:** реализован аппаратный пробник для Acer `168c:003e`, subsystem `11ad:0807`, ревизия `32`. `wifi probe` пытается получить BMI Target Info после PCI/D0/wake, cold/warm reset и настройки CE0/CE1/CE7 и ранней конфигурации ROM. `wifi load` дополнительно загружает прошивку и проверяет HTC/WMI ready, затем останавливает карту. `wifi scan` пассивно ищет AP в 2,4 ГГц и на выбранных каналах 5 ГГц; на Acer подтверждены HTT 3.87 и список из 18 AP с Galaxy S23; стабильность повторных серий ещё не подтверждена. `wifi connect N` реализует ассоциацию WPA2 и HTT/Ethernet/DHCP, `wifi disconnect` останавливает карту; подключение на Acer ещё не подтверждено.

## Как работает {#how}

Проверка запускается только командой оболочки. Сначала проверяются точные PCI ID/revision и контейнеры прошивки/плат. BAR0 должен быть выровнен на 1 МиБ и весь нужный диапазон находиться ниже 4 ГиБ. Страницы прямого отображения MMIO переводятся в uncached. Затем карта переводится в D0 без ASPM/CLKREQ, выставляется SOC_WAKE, с ограничением проверяется RTC=ON.

Для QCA6174 используется последовательность cold reset, ожидания target initialized и warm reset. Во время cold reset после записи global reset нет PCIe-чтения до задержки 20 мс. INTx отключён в PCI command; CE-прерывания маскируются. Во время ожидания ROM повторяется запись в регистр разрешения событий PCIe core для устранения гонки отображения регистров, при отключённом INTx на хосте. Отсутствующий/сбойный target даёт ошибку, а не бесконечное ожидание.

Девять zeroed DMA-страниц ниже 4 ГиБ содержат кольца CE0 source, CE1 destination, запрос, ответ и два кольца диагностического CE7, кольцо CE2, исходящие кольца CE3/CE4. После ROM отдельно выделяются 32 КиБ под 16 независимых WMI-буферов по 2048 байт. CE2 публикует 15 дескрипторов, один слот остаётся пустым; завершённый буфер копируется до очистки и повторного использования. Это заменяет один выставленный буфер, который не вмещал поток событий сканирования между опросами. CE7 имеет два элемента; с его помощью читается `hi_interconnect_state`, записываются target pipe config, service map, отключение L1 и early allocation для девяти банков IRAM hw3.2. После `HI_OPTION_EARLY_CFG_DONE` и проверки записи процессору карты посылается сигнал через PCIe core control. Только затем разрешён BMI; `target initialized=2` само по себе ещё не означает готовность BMI. Адреса ROM проверяются на выравнивание и попадание в RAM target до начала DMA. Хост настраивает только свои половины CE0/CE1, сохраняя противоположные кольца ROM. Для BMI-пробника размер колец 16, дескриптор 8 байт, за один раз опубликован один запрос. BMI GET_TARGET_INFO возвращает 12 байт: размер, версию и тип target. Сейчас принимается версия `0x05030000`; другая сохраняется в отчёте и возвращает `EOPNOTSUPP`. `wifi probe` завершает проверку без BMI_DONE; `wifi load` продолжает запуск, описанный ниже.

`wifi load` использует BMI-команды по 256 байт: PLL выбирается по EFUSE, настраиваются host-interest/endianness, передаются ровно 8124 байта точной платы, OTP и основной SGMT-образ через LZ stream. Последнее слово дополнено нулями, stream закрывается адресом 0 для сброса кэша ROM. Результат OTP учитывает feature IGNORE_OTP_RESULT встроенной прошивки. OTP выполняет калибровку, команды записи flash/OTP не используются. Перед BMI_DONE публикуется приёмный дескриптор CE1; сообщение HTC ready проверяется по endpoint, длинам, message ID, credits и размеру credit. Затем HTC подключает HTT/WMI services и посылает SETUP_COMPLETE_EX. CE2 может сначала получить WMI SERVICE_AVAILABLE (ID 3, TLV `0x22f`, 20 байт), затем SERVICE_READY (ID 1). `wmi::wait_service_ready` проверяет длины предварительного сообщения и продолжает ожидание: его расширенная таблица сервисов не нужна текущему station-драйверу и не заменяет готовность. Не более 32 событий и один срок 5 секунд на всю последовательность; он не продлевается при каждом пакете. Только SERVICE_READY проходит проверки ABI, числа RF chains, базовой таблицы сервисов и ограниченных запросов памяти. INIT описывает только принадлежащую драйверу zeroed память ниже 4 ГиБ; количество units соответствует ресурсам vdev/peers. Предел — 1 МиБ на запрос и 8 МиБ суммарно. Событие WMI ready проверяется по ABI, успешному status и корректному MAC. Это ещё не ассоциация или подключение. Прогресс печатается каждые 64 КиБ; общий предел после ROM — 120 секунд, доступна отмена Ctrl+C.

HTC trailer разбирается как последовательность записей: заголовок 4 байта (`id`, `len`, два байта дополнения), каждый credit report также 4 байта (`endpoint`, `credits`, два байта дополнения). `len` не включает заголовок. Дополнение не считается новым endpoint или записью; неизвестные записи пропускаются с проверкой границ. Пакет только с trailer возвращает credits, но не выдаётся как WMI/HTT event. При ошибке приёма сохраняются CE, длина и заголовок HTC; перед разбором версии HTT сохраняются длина и первые слова ответа.

Перед освобождением страниц DMA отключается PCI bus mastering, маскируются события, кольца останавливаются и их размеры обнуляются. Это выполняется также при тайм-ауте. После `wifi load` CPU карты дополнительно останавливается cold reset перед освобождением DMA, включая ошибку и отмену. Пробник не подключён к smoltcp и не изменяет Ethernet-интерфейс. После проверки для дальнейшего запуска Wi-Fi потребуется новая инициализация.

Команда `wifi scan` создаёт station vdev и выполняет три пассивных прохода с разными scan ID в одной загрузке firmware. Результаты объединяются по BSSID и не стираются, если последующий проход пропустил сеть. Список ограничен factory channel limits: 2,4 ГГц, каналы 1–13, и 5 ГГц, каналы 36–48 и 149–165 с шагом 4. DFS и канал 14 исключены. Каждый канал имеет passive flag, мощность 0; активные probe requests не включаются. Длительность пассивного прослушивания — 200 мс на канал; повторные scan ID и TLV-полярность FILTER_PROBE_REQ следуют ABI. Каждый проход имеет общий срок 15 секунд и предел 4096 событий; общий срок загрузки 120 секунд сохраняется. События foreign-channel/exit запрашиваются вместе с started/completed/start-failed. Сохраняются длительности, число WMI-событий, посещений каналов, управляющих кадров, ошибочных WMI/beacon и найденных AP: пустой список больше не остаётся единственной диагностикой.

WMI events проходят через ограниченную очередь; HTC credits учитываются с trailer и CE1, и CE2, а командный буфер не переиспользуется до завершения DMA. Beacon/probe-response парсер проверяет SSID, BSSID, IE/RSN длины, CCMP/PSK и обязательный PMF. Повреждённые кадры пропускаются; счётчик AP ограничен 20. Управляющие символы SSID экранируются при выводе. `station::unsupported_reason` используется и при выводе, и перед подключением: сообщает конкретную причину отказа, включая отсутствие RSN, group/pairwise CCMP, PSK, обязательный PMF, скрытый SSID, basic rates и канал подключения. Обнаружение на дополнительных каналах не разрешает ассоциацию там: STA по-прежнему допускает только каналы 1–11. Результаты копируются из WIFI_SCAN перед печатью. После команды target останавливается.

## HTT и подключение {#station}

`wifi load` теперь проверяет также HTT version 3 и публикует RX-кольцо: 128 записей, 63 буфера по 2048 байт, descriptor v1 размером 300 байт. Layout сверён с `sizeof/offsetof` ath10k v6.12. Один TX-буфер закреплён до HTT completion, даже если CE уже прочитал команду. Перед ответом версии допустимы HTT TX_CREDIT_UPDATE (ID `0x0f`, не менее 4 байт): они проверяются и пропускаются, поскольку драйвер использует TX completions без HTT credit flow control. `htt::wait_version` допускает не более 32 пакетов с единым сроком 3 секунды; другие события и повреждённые сообщения дают ошибку. Версия по-прежнему должна быть 3. Повреждённые/повторные completion IDs и неизвестные RX DMA-адреса отвергаются. RX проверяет MSDU_DONE, длины, BSSID, ошибки FCS/MIC/decrypt, Ethernet decap и CCMP PN по ключу/TID. Начальная STA не согласует HT/VHT/A-MSDU/802.11 fragmentation. Offload без PN пропускает только EAPOL, который затем проверяет WPA2; прикладные пакеты через него не выдаются.

`wifi connect N` выбирает сохранённую AP, принимает пароль без эха и получает PMK. После новой загрузки создаются station vdev и DEFAULT peer, задаётся канал, выполняются open authentication и association с SSID/legacy rates/RSN. Нужны подтверждения start, peer map, ответов AP и AID. PTK/GTK устанавливаются через WMI; подтверждение — HTT SEC_IND. После M4 TX и авторизации peer карта передаётся потоку ядра. Допускаются видимые WPA2-PSK/CCMP AP на каналах 1–11, без обязательного PMF; мощность ограничена 0 dBm, только 11g/20 MHz. RDRAND проверяется через CPUID; ограниченные повторы и проверка застрявшего источника, без псевдослучайного fallback.

Перед auth создаётся `WMI_PEER_TYPE_DEFAULT`, как при STA_NONE в ath10k. Тип BSS здесь не заменяет обычного station peer. Vdev получает Native WiFi TX encapsulation даже при Ethernet offload: формат management или Ethernet задаёт HTT-дескриптор каждого кадра. C-эталоны используют enum из `wmi.h` и `hw.h`, закрепляя эти решения вместе с layout.

Одна AP может иметь несколько HTT peer ID: на фото Galaxy S23 пришли `0x0f` и `0x7f`. Ограниченная таблица из 2048 бит (пространство ID RX-дескриптора) заменяет перезапись одного номера. RX и SEC_IND допускают любой текущий ID выбранной AP; replay остаётся общим для AP/ключа. Unmap удаляет один ID, а потеря последнего закрывает авторизацию. Переназначение ID чужому MAC удаляет прежнюю привязку.

Кроме TX_COMPL_IND, парсер принимает HTT MGMT_TX_COMPLETION (`0x0e`, 20 байт) с проверкой ID/status. Он завершает только ожидающий management-буфер; чужой тип, неизвестный или повторный completion не освобождает DMA. Обычные Ethernet completion не печатаются на каждый пакет. В auth/association раздельно сохраняются отправленный TX ID, ожидание TX completion и ответа AP; при тайм-ауте сохраняются CE4 и счётчики WMI/management/HTT, отбрасываний и последнего HTT ID.

Сценарии ядра проверяют оба ID `15/127` через SEC_IND и RX, общий replay, сохранение авторизации после первого unmap и закрытие после последнего; management completion не может освободить Ethernet-слот или повторно завершить DMA. Эти проверки не подтверждают auth в эфире.

Перед передачей EAPOL в автомат WPA2 проверяются Ethernet source выбранного AP и destination нашей станции, в том числе после авторизации. Зашифрованный кадр, который AP переслал от другого Ethernet-источника, не получает права начинать новый обмен ключами. Остальные прикладные кадры требуют установленного ключа, авторизации и проверки PN.

`bridge.rs` передаёт Ethernet-кадры в smoltcp через очереди до 64 пакетов; EAPOL остаётся у драйвера. Поколение соединения отзывает старые TX tokens. Переключение сетевой карты запрещено при открытых TCP/ICMP/DNS и сохраняет монотонные socket IDs; прежняя карта освобождается вне NETWORK. Потеря AP, beacon miss/peer kickout, ошибка DMA или `wifi disconnect` очищают link, IP, маршрут, DNS и прерывают TCP. После остановки/reset DMA-страницы обнуляются и возвращаются аллокатору. Тайм-аут загрузки отключается только для работающего фонового потока; он не читает ввод оболочки.

Неотвеченный HTT TX имеет срок 5 секунд: буфер остаётся закреплённым до reset, а worker сообщает `HTT TX completion timeout`. Запрос отключения проверяется в ожиданиях CE и station. WMI-буфер обнуляется сразу после CE source completion, чтобы PTK/GTK не оставались в общей DMA-странице. Слишком длинный или повреждённый ввод пароля поглощается до конца строки без эха: его суффикс не попадает в оболочку. Эти границы проверяются тестами кода и ядра.

## WPA2 {#wpa2}

`osel-core/src/wifi/wpa2.rs` реализует чистый автомат WPA2-PSK/CCMP: PBKDF2-HMAC-SHA1, PTK, MIC и AES key unwrap. Криптографические примитивы — RustCrypto; лицензии зависимостей включены в каждый ramdisk как `/usr/share/licenses/WPA2-NOTICES`. Пароль — 8–63 байта или 64 шестнадцатеричных символа PSK; секреты обёрнуты в `Zeroizing`.

Автомат проверяет replay counter, ANonce, MIC и RSN/GTK KDE. Ключи выдаются вызывающему коду один раз; авторизация требует явного подтверждения установки и отправки M4. Повтор M3 вызывает повтор M4 без установки ключей. Аналогично обрабатывается group rekey; тот же GTK с новым индексом отвергается. SNonce требует криптографический источник случайности без резервного генератора по времени. Автомат используется аппаратной ассоциацией и фоновым обработчиком rekey.

Для target ядра выставлен `aes_force_soft`, SHA1 использует `force-soft`: AES-NI/SHA-инструкции с XMM нарушили бы сохранность регистров пользовательских потоков. Тест ядра выполняет PBKDF2 и AES unwrap с шаблонами во всех 16 XMM и проверяет сохранность состояния в UEFI и BIOS. Хостовые тесты сверяют PMK/PTK и RFC3394 с известными векторами, моделируют M1–M4, повторы, group rekey, неверные MIC, nonce и replay.

## Прошивка и плата {#firmware}

В `firmware/` хранятся неизменённые `firmware-6.bin`, `board-2.bin`, лицензия и обязательное уведомление. Источник, дата и SHA256 записаны в `firmware/manifest.json`; `tools/check-firmware.py` сверяет точные байты в CI. Из `board-2.bin` выбирается только точная запись PCI-платы LiteOn `11ad:0807`, размер 8124 байт, без fallback на чужую калибровку.

Парсер проверяет magic с NUL, выравнивание 4, вложенные TLV, длины и переполнения. Дублированные обязательные поля отвергаются. Встроенная прошивка должна содержать WMI TLV=4, HTT=3 и OTP. Версия и размеры доступны через `wifi fw`; надпись bundled не означает running.

Runner всегда кладёт лицензию и уведомление в `/usr/share/licenses/ath10k/LICENSE` и `/usr/share/licenses/ath10k/NOTICE` и лицензию адаптированного драйвера `DRIVER-ISC`, включая пользовательский `OSEL_RAMDISK`. Эти пути зарезервированы; их замена или файл вместо родительского каталога дают ошибку упаковки. Программы на машине владельца для этого не устанавливаются.

## Код {#code}

- `src/drivers/qca6174.rs`: аппаратный пробник, ограниченные ожидания и снимок последних этапов.
- `src/drivers/pci.rs`, `src/drivers/dma.rs`: PCI и страницы DMA.
- `osel-core/src/wifi.rs`: встроенные файлы и проверяемый парсер контейнеров.
- `osel-core/src/wifi/ieee80211.rs`: beacon, SSID и RSN.
- `osel-core/src/wifi/wmi.rs`: WMI TLV, service-ready/ready и построение INIT.
- `osel-core/src/wifi/bmi.rs`, `osel-core/src/wifi/htc.rs`: протокол загрузки и проверка первого ответа прошивки.
- `osel-core/src/wifi/boot.rs`: порядок ранней конфигурации ROM, таблицы ABI, проверка адресов и тестируемый интерфейс CE7.
- `src/diagnostics.rs`, `src/shell.rs`: общий отчёт и команды; [пользовательская диагностика](../../../user/diagnostics.md).
- `runner/src/main.rs`: обязательные лицензионные файлы в образах.

## Блокировки и инварианты {#locks}

Атомарный BUSY разрешает одну проверку. Его guard сбрасывает флаг на всех обычных путях выхода. `WIFI_REPORT` защищает только копируемый отчёт из 64 записей; ни сон, ни MMIO, ни печать не выполняются под этой блокировкой. Пробник принадлежит вызывающему потоку, ожидания выполняются с включёнными IRQ; в IRQ его вызывать нельзя. Нет вложения `NETWORK` и `WIFI_REPORT`. `WIFI_HANDOFF` используется только для перемещения владения в worker. `WIFI_LINK` содержит ограниченные очереди; порядок NETWORK -> WIFI_LINK, обратного вложения нет.

В начале каждой попытки отчёт очищается. Последний завершённый этап и errno остаются после возврата команды. `wifi regs` показывает последние 22 записи снимка, чтобы они помещались на экране; регистры повторно не читает. При тайм-ауте до очистки сохраняются PCI command/BME, PCIe core control, базы/размеры колец, control/command, индексы чтения/записи и ошибки проблемного CE. Биты `CE error status` маскируются по `0x7e0`: младший бит сырого регистра не является ошибкой DMA. Этапы печатаются на экране и в COM1 до завершения всей проверки.

## Грабли {#pitfalls}

- QEMU не эмулирует QCA6174. Зелёный CI доказывает парсер, отсутствие карты и освобождение ресурсов, но не работу PCIe/reset/CE на Acer.
- Без early config и сигнала CPU ROM может выставить initialized, но не потреблять BMI. Нельзя очищать кольца, принадлежащие ROM.
- PCI ревизия не заменяет BMI target version; для продолжения запуска требуется аппаратный отчёт.
- Не включать bus mastering до публикации валидных колец; не освобождать DMA при включённой карте.
- Не переносить ожидание через `IrqSpinlock`: потеря PIT превратит ограниченный тайм-аут в зависание.
- Firmware API 6 отличается от интерфейса передачи пакетов HTT. Наличие файлов не даёт WPA2 или DHCP.

## Тесты {#tests}

`cargo test-core` проверяет настоящие встроенные контейнеры, точное совпадение платы, truncation, неправильные длины, magic и дубли. Тест ядра проверяет отсутствие карты и снятие BUSY/освобождение ресурсов при повторных попытках. `tests/shell.rs` и `tools/check-shell.py` проверяют команды, отчёт и наличие лицензии в образах. На Acer с образом `a53f703` владелец 2026-10-15 подтвердил PCI, RTC `0x73`, chip ID `0x00340aff` и три успешных ожидания initialized `2`. CE0 не потреблял первый запрос BMI (read index `0`, error status `0`, `ETIMEDOUT`); оболочка оставалась доступной. Это выявило пропуск ранней конфигурации ROM и сигнала CPU. На образе `8a7c625` CE7 и BMI подтверждены владельцем: размер 12 байт, version `0x05030000`, type `8`, error=None. Владелец также прислал фотографии запуска v0.12: прошивка передана, BMI_DONE выполнен, HTC ready получен, сервисы HTT/WMI подключены. Первым WMI-пакетом пришёл SERVICE_AVAILABLE (`00000003 022f0014 00000000 08001000`), который прежний код ошибочно принимал за SERVICE_READY и завершал с `EIO`. После исправления SERVICE_AVAILABLE владелец подтвердил SERVICE_READY, INIT и WMI ready; следующий запуск завершился с `EIO` на этапе `HTT version wait`. Старый отчёт не различал ошибку trailer и ошибку HTT event. Сверка с ABI выявила неверный двухбайтовый шаг записей HTC credits; новый код использует четырёхбайтовые структуры и сохраняет заголовки при отказе. Следующие фотографии подтвердили HTT 3.87 (`00035700`), RX ring и завершённый scan без ошибки. Один из пяти запусков обнаружил пять AP, включая Rostel-6 с неподдерживаемой защитой; точная причина отказа старым образом не записана. Остальные запуски вернули пустой список. Следующая фотография нового образа подтвердила 18 AP, включая Galaxy S23 на 2422 МГц. Первый auth завершился ETIMEDOUT после `STA open authentication begin`, до WPA2; старый отчёт не различает TX completion и ответ AP. Пришли два peer map выбранной AP (`0x0f`, `0x7f`). Исправлены отличия настройки peer/vdev от ath10k и учёт набора ID; успешная аутентификация и подключение ещё не подтверждены. Тесты модели ROM проверяют конфигурацию до сигнала CPU, сохранение флагов, отказ на повреждённых указателях и тайм-аут DMA без сигнала готовности.

`DmaRegion` в `src/drivers/dma.rs` выделяет непрерывные страницы, ограниченно удерживая кандидатов из LIFO-кэша до нахождения последовательности; лишние кандидаты возвращаются также при ошибке. Vec выделяется до MEMORY, под блокировкой нет выделения кучи или сна. Тест ядра повторяет выделение после возврата страниц в обратном порядке, проверяет zeroed bytes, непрерывность, границу 4 ГиБ и отсутствие утечек. Прошивка останавливается до освобождения этих областей.

Модель BMI проверяет настоящие firmware/OTP/board, порядок команд, все восемь опорных частот, сохранение битов PLL, границы блоков и нулевое дополнение, тайм-аут, короткий ответ и запрет повторного BMI_DONE. Парсеры HTC/WMI проверяют обрезанные/дублированные TLV, ABI, endpoint/service/status, размеры запросов и событие ready. INIT тестируется на согласованность ресурсов и реально предоставленной памяти. Регрессия WMI использует видимый на фото префикс SERVICE_AVAILABLE и проверяет его перед SERVICE_READY, отсутствие предварительного события, повторы, повреждённые/дублированные TLV, сохранение проверки ABI, ошибки транспорта и предел 32 события. Тесты HTC используют четырёхбайтовые заголовки и отчёты с ненулевым дополнением, несколько записей, credit-only и HTT version пакеты; проверяются усечения, неверные длины и endpoint.

## Аудит ABI {#abi-audit}

Официальный [Qualcomm product brief](https://www.qualcomm.com/content/dam/qcomm-martech/dm-assets/documents/qca6174a-product-brief_87-yb799-1-c.pdf) описывает возможности QCA6174A, но не протокол программирования firmware. Программный эталон — определения ISC-драйвера [ath10k v6.12](https://github.com/torvalds/linux/tree/v6.12/drivers/net/wireless/ath/ath10k). Board data содержит калибровку конкретной платы, а не описание ABI; сохраняется точный выбор LiteOn `11ad:0807` и контрольные суммы из `firmware/manifest.json`.

| Проверено | Эталон и автоматические проверки |
|---|---|
| PCI/ROM, CE и BMI upload | `pci.c`, `hw.h`, `bmi.h`; модель ROM и настоящие firmware/board в существующих тестах |
| HTC и начало HTT | `htc.h`, `htt.h`; предварительные события, четырёхбайтовые credit records, трейлеры control/ready, общий срок и предел событий |
| WMI boot, scan, station и keys | `wmi.h`, `wmi-tlv.h/c`; полные бинарные команды, размеры, TLV tags, enum IDs, порядок полей и нулевое дополнение |
| HTT RX/TX | `htt.h`, `rx_desc.h`; исходящие дескрипторы/prefetch, `sizeof`/`offsetof` RX, peer map/unmap, SEC_IND и TX completion |
| Владение DMA | сценарий ядра под UEFI/BIOS: реальные страницы, возврат RX-буфера, неизвестный адрес, повтор completion, раздельные PTK/GTK acknowledgements и потеря peer |
| Ввод с эфира | усечения, мутации битов валидных событий и детерминированные повреждённые пакеты; EAPOL только от выбранного AP, MIC/replay и известные криптографические векторы |

`osel-core/tests/wifi_abi.rs` читает эталоны из `osel-core/tests/fixtures/ath10k-v6.12/`. Они созданы C-компилятором из исходных структур и enum, а не Rust-энкодерами. `sources.json` закрепляет SHA256 шести исходных заголовков. Для независимой перепроверки скачайте перечисленные заголовки из закреплённого v6.12 в одну папку и выполните:

```shell
python3 tools/check-wifi-abi.py --reference-dir /tmp/ath10k-v6.12
```

`tools/wifi-abi-cases.c` задаёт синтетические примеры; Python извлекает декларации из проверенных заголовков, компилирует их во временной папке и сравнивает байты. `--update` пересоздаёт эталоны после осознанной правки сценариев, не отменяя проверку исходных SHA256. Обычный `cargo test-core` не требует C-компилятора, сети или установки Linux headers.

Эти проверки находят программные расхождения ABI и ошибки обработки событий. Они не моделируют радиочасть, аналоговые задержки, RF-kill и внутреннее состояние закрытой прошивки. По фотографиям подтверждены WMI ready, HTT 3.87 и список из 18 AP с Galaxy S23; стабильность повторного поиска, WPA2 и DHCP на Acer остаются аппаратными контрольными точками. Пустой список не доказывает отсутствие сетей: проверяйте счётчики приёма. Galaxy S23 найден на канале 3 с совместимым RSN, первый auth завершился тайм-аутом; новый пассивный список расширяет поиск, но не обещает обнаружение на DFS/6 ГГц.

Продолжение — [план Wi-Fi](../../design/wifi.md). Последняя сверка: 2026-10-16, ветка `fix-wifi-wmi-startup`.

Регрессии сканирования: сценарий ядра заполняет 15 реальных DMA-буферов до чтения, проверяет порядок 120 сообщений через wrap и отказы по длине без перемещения индексов. Host-тесты объединяют пустые и непустые проходы, проверяют scan ID, счётчики повреждённых кадров, ограничения диапазонов и согласованность причин отказа с ассоциацией. C-эталон отдельно проверяет MODE_11A/passive для 5 ГГц. Эти сценарии не воспроизводят эфир или работу закрытой прошивки.
