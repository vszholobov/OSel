# Wi-Fi QCA6174

**Для кого:** разработчик аппаратного драйвера и запуска прошивки.

**Коротко:** реализован аппаратный пробник для Acer `168c:003e`, subsystem `11ad:0807`, ревизия `32`. `wifi probe` пытается получить BMI Target Info после PCI/D0/wake, cold/warm reset и настройки CE0/CE1/CE7 и ранней конфигурации ROM. `wifi load` дополнительно загружает прошивку и проверяет HTC ready, затем останавливает карту. Сканирование, ассоциация, WPA2 и передача пакетов не реализованы.

## Как работает {#how}

Проверка запускается только командой оболочки. Сначала проверяются точные PCI ID/revision и контейнеры прошивки/плат. BAR0 должен быть выровнен на 1 МиБ и весь нужный диапазон находиться ниже 4 ГиБ. Страницы прямого отображения MMIO переводятся в uncached. Затем карта переводится в D0 без ASPM/CLKREQ, выставляется SOC_WAKE, с ограничением проверяется RTC=ON.

Для QCA6174 используется последовательность cold reset, ожидания target initialized и warm reset. Во время cold reset после записи global reset нет PCIe-чтения до задержки 20 мс. INTx отключён в PCI command; CE-прерывания маскируются. Во время ожидания ROM повторяется запись в регистр разрешения событий PCIe core для устранения гонки отображения регистров, при отключённом INTx на хосте. Отсутствующий/сбойный target даёт ошибку, а не бесконечное ожидание.

Шесть zeroed DMA-страниц ниже 4 ГиБ содержат кольца CE0 source, CE1 destination, запрос, ответ и два кольца диагностического CE7. CE7 имеет два элемента; с его помощью читается `hi_interconnect_state`, записываются target pipe config, service map, отключение L1 и early allocation для девяти банков IRAM hw3.2. После `HI_OPTION_EARLY_CFG_DONE` и проверки записи процессору карты посылается сигнал через PCIe core control. Только затем разрешён BMI; `target initialized=2` само по себе ещё не означает готовность BMI. Адреса ROM проверяются на выравнивание и попадание в RAM target до начала DMA. Хост настраивает только свои половины CE0/CE1, сохраняя противоположные кольца ROM. Для BMI-пробника размер колец 16, дескриптор 8 байт, за один раз опубликован один запрос. BMI GET_TARGET_INFO возвращает 12 байт: размер, версию и тип target. Сейчас принимается версия `0x05030000`; другая сохраняется в отчёте и возвращает `EOPNOTSUPP`. `wifi probe` завершает проверку без BMI_DONE; `wifi load` продолжает запуск, описанный ниже.

`wifi load` использует BMI-команды по 256 байт: PLL выбирается по EFUSE, настраиваются host-interest/endianness, передаются ровно 8124 байта точной платы, OTP и основной SGMT-образ через LZ stream. Последнее слово дополнено нулями, stream закрывается адресом 0 для сброса кэша ROM. Результат OTP учитывает feature IGNORE_OTP_RESULT встроенной прошивки. OTP выполняет калибровку, команды записи flash/OTP не используются. Перед BMI_DONE публикуется приёмный дескриптор CE1; сообщение HTC ready проверяется по endpoint, длинам, message ID, credits и размеру credit. Это ещё не WMI service-ready или подключение. Прогресс печатается каждые 64 КиБ; общий предел после ROM — 120 секунд, доступна отмена Ctrl+C.

Перед освобождением страниц DMA отключается PCI bus mastering, маскируются события, кольца останавливаются и их размеры обнуляются. Это выполняется также при тайм-ауте. После `wifi load` CPU карты дополнительно останавливается cold reset перед освобождением DMA, включая ошибку и отмену. Пробник не подключён к smoltcp и не изменяет Ethernet-интерфейс. После проверки для дальнейшего запуска Wi-Fi потребуется новая инициализация.

## Прошивка и плата {#firmware}

В `firmware/` хранятся неизменённые `firmware-6.bin`, `board-2.bin`, лицензия и обязательное уведомление. Источник, дата и SHA256 записаны в `firmware/manifest.json`; `tools/check-firmware.py` сверяет точные байты в CI. Из `board-2.bin` выбирается только точная запись PCI-платы LiteOn `11ad:0807`, размер 8124 байт, без fallback на чужую калибровку.

Парсер проверяет magic с NUL, выравнивание 4, вложенные TLV, длины и переполнения. Дублированные обязательные поля отвергаются. Встроенная прошивка должна содержать WMI TLV=4, HTT=3 и OTP. Версия и размеры доступны через `wifi fw`; надпись bundled не означает running.

Runner всегда кладёт лицензию и уведомление в `/usr/share/licenses/ath10k/LICENSE` и `/usr/share/licenses/ath10k/NOTICE` и лицензию адаптированного драйвера `DRIVER-ISC`, включая пользовательский `OSEL_RAMDISK`. Эти пути зарезервированы; их замена или файл вместо родительского каталога дают ошибку упаковки. Программы на машине владельца для этого не устанавливаются.

## Код {#code}

- `src/drivers/qca6174.rs`: аппаратный пробник, ограниченные ожидания и снимок последних этапов.
- `src/drivers/pci.rs`, `src/drivers/dma.rs`: PCI и страницы DMA.
- `osel-core/src/wifi.rs`: встроенные файлы и проверяемый парсер контейнеров.
- `osel-core/src/wifi/bmi.rs`, `osel-core/src/wifi/htc.rs`: протокол загрузки и проверка первого ответа прошивки.
- `osel-core/src/wifi/boot.rs`: порядок ранней конфигурации ROM, таблицы ABI, проверка адресов и тестируемый интерфейс CE7.
- `src/diagnostics.rs`, `src/shell.rs`: общий отчёт и команды; [пользовательская диагностика](../../../user/diagnostics.md).
- `runner/src/main.rs`: обязательные лицензионные файлы в образах.

## Блокировки и инварианты {#locks}

Атомарный BUSY разрешает одну проверку. Его guard сбрасывает флаг на всех обычных путях выхода. `WIFI_REPORT` защищает только копируемый отчёт из 64 записей; ни сон, ни MMIO, ни печать не выполняются под этой блокировкой. Пробник принадлежит вызывающему потоку, ожидания выполняются с включёнными IRQ; в IRQ его вызывать нельзя. Нет вложения `NETWORK` и `WIFI_REPORT`.

В начале каждой попытки отчёт очищается. Последний завершённый этап и errno остаются после возврата команды. `wifi regs` показывает последние 22 записи снимка, чтобы они помещались на экране; регистры повторно не читает. При тайм-ауте до очистки сохраняются PCI command/BME, PCIe core control, базы/размеры колец, control/command, индексы чтения/записи и ошибки проблемного CE. Биты `CE error status` маскируются по `0x7e0`: младший бит сырого регистра не является ошибкой DMA. Этапы печатаются на экране и в COM1 до завершения всей проверки.

## Грабли {#pitfalls}

- QEMU не эмулирует QCA6174. Зелёный CI доказывает парсер, отсутствие карты и освобождение ресурсов, но не работу PCIe/reset/CE на Acer.
- Без early config и сигнала CPU ROM может выставить initialized, но не потреблять BMI. Нельзя очищать кольца, принадлежащие ROM.
- PCI ревизия не заменяет BMI target version; для продолжения запуска требуется аппаратный отчёт.
- Не включать bus mastering до публикации валидных колец; не освобождать DMA при включённой карте.
- Не переносить ожидание через `IrqSpinlock`: потеря PIT превратит ограниченный тайм-аут в зависание.
- Firmware API 6 отличается от интерфейса передачи пакетов HTT. Наличие файлов не даёт WPA2 или DHCP.

## Тесты {#tests}

`cargo test-core` проверяет настоящие встроенные контейнеры, точное совпадение платы, truncation, неправильные длины, magic и дубли. Тест ядра проверяет отсутствие карты и снятие BUSY/освобождение ресурсов при повторных попытках. `tests/shell.rs` и `tools/check-shell.py` проверяют команды, отчёт и наличие лицензии в образах. На Acer с образом `a53f703` владелец 2026-10-15 подтвердил PCI, RTC `0x73`, chip ID `0x00340aff` и три успешных ожидания initialized `2`. CE0 не потреблял первый запрос BMI (read index `0`, error status `0`, `ETIMEDOUT`); оболочка оставалась доступной. Это выявило пропуск ранней конфигурации ROM и сигнала CPU. На образе `8a7c625` CE7 и BMI подтверждены владельцем: размер 12 байт, version `0x05030000`, type `8`, error=None. Новый путь загрузки прошивки/HTC ещё требует проверки на Acer. Тесты модели ROM проверяют конфигурацию до сигнала CPU, сохранение флагов, отказ на повреждённых указателях и тайм-аут DMA без сигнала готовности.

Модель BMI проверяет настоящие firmware/OTP/board, порядок команд, все восемь опорных частот, сохранение битов PLL, границы блоков и нулевое дополнение, тайм-аут, короткий ответ и запрет повторного BMI_DONE. Парсер HTC проверяет обрезанные и некорректные пакеты.
