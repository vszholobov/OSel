# План

**Для кого:** для всех, кто хочет знать, что уже сделано и что дальше.

**Коротко:** цель — запустить на OSel консольный [тетрис на Go](https://github.com/vszholobov/Tetris), сначала в QEMU, потом на ноутбуке с флешки. Go-программа собирается как обычная программа для Linux, ядро реализует нужные ей системные вызовы Linux ([решение 0005](decisions/0005-linux-abi-for-go.md)). Сетевая игра — по желанию, отдельным этапом. Разработка и отладка идут в QEMU, ноутбук включается на контрольных точках.

Пока этап в работе, его подробности лежат в `design/`. PR, который закрывает этап, переносит их в описание устройства и решения ([правило](guides/writing-docs.md#single-home)).

## Этап 1. Ядро — проверено на компьютере владельца {#stage-1}

- [x] Загрузка через `bootloader` 0.11 в режимах UEFI и BIOS, вывод текста в framebuffer ([решение 0001](decisions/0001-bootloader-0.11-and-uefi.md)).
- [x] Аппаратные прерывания: таймер 100 Гц, клавиатура PS/2, `hlt` вместо пустого цикла ([прерывания](architecture/core/interrupts.md), [клавиатура](architecture/drivers/keyboard.md)).
- [x] Страничная память и куча; ядро в верхней половине адресов ([память](architecture/core/memory.md), [решение 0006](decisions/0006-higher-half-kernel.md)).
- [x] Экран паники с адресом и регистрами, обработчики всех исключений процессора.
- [x] Блокировки, которые сами выключают прерывания и сообщают о взаимоблокировке ([блокировки](architecture/core/locking.md)).
- [x] Тесты на хосте, в QEMU и в CI, проверка утечек кучи ([как устроены тесты](architecture/testing.md)).
- [ ] Скрипт записи образа на флешку — отложен, пока запись описана вручную на странице [«Запуск с флешки»](../user/usb.md).
- [x] **Проверка на реальном компьютере:** владелец подтвердил загрузку OSel и работу тетриса 2026-10-14. Модель и режим прошивки ещё не записаны; отдельная проверка Samsung остаётся неподтверждённой.

## Этап 2. Запуск программ — сделан {#stage-2}

Завершён в [PR №7](https://github.com/vszholobov/OSel/pull/7): статическая Go-программа запускается, выполняет горутины с `time.Sleep` и завершается. Устройство — [программы](architecture/core/programs.md), [потоки](architecture/core/threads.md) и [системные вызовы](reference/syscalls.md).

- [x] Ramdisk: архив cpio из папки `ramdisk/`, интерфейсы блочного устройства и файловой системы, ошибки Linux ([файлы и ramdisk](architecture/core/fs.md), [решение 0007](decisions/0007-storage-interfaces.md)).
- [x] Освобождение физических страниц, проверка утечек страниц в тестах ([память](architecture/core/memory.md#frames), [решение 0008](decisions/0008-frame-pool.md)).
- [x] Адресное пространство программы ([память](architecture/core/memory.md#address-spaces), [решение 0009](decisions/0009-shared-kernel-half.md)).
- [x] Загрузка ELF из ramdisk, стартовый стек с argv, envp и auxv ([программы](architecture/core/programs.md), [решение 0010](decisions/0010-static-elf-loader.md)).
- [x] Пользовательский режим: сегменты кольца 3 в GDT, стек ядра в TSS, исключения программы не роняют ядро ([пользовательский режим](architecture/core/user-mode.md), [решение 0011](decisions/0011-user-entry.md)).
- [x] Вход в ядро через `syscall`/`sysret`, системные вызовы `write` и `exit`. **Проверка:** программа на ассемблере из ramdisk печатает «Hello from ring 3!» ([системные вызовы](reference/syscalls.md), [решение 0012](decisions/0012-syscall-entry-and-user-programs.md)).
- [x] SSE для пользовательских программ ([x87 и SSE](architecture/core/user-mode.md#fpu), [решение 0013](decisions/0013-fpu-state.md)).
- [x] Потоки и планировщик с вытеснением по таймеру ([потоки и планировщик](architecture/core/threads.md), [решение 0015](decisions/0015-threads.md)).
- [x] `clone` и `futex` ([потоки](architecture/core/threads.md#clone), [ожидание](architecture/core/threads.md#futex)).
- [x] Системные вызовы Linux для рантайма Go ([справочник](reference/syscalls.md)). **Проверка:** Go-программа «hello world».
- [x] Таймеры и упрощённое ожидание событий: `nanosleep`, `clock_gettime`, `epoll` и `eventfd`. **Проверка:** Go-программа с горутинами и `time.Sleep` ([сквозной тест](architecture/core/programs.md#go)).

## Этап 2.5. Дочерние программы — сделан {#stage-2-5}

Go запускает программы через `os/exec`. Устройство и ограничения — [процессы](architecture/core/threads.md#process), [системные вызовы](reference/syscalls.md).

- [x] Процессы с PID, родителем и ожиданием завершения ребёнка.
- [x] Создание дочернего процесса через `clone` с семантикой `vfork`, затем `execve`; существующее создание потоков Go продолжает работать.
- [x] Наследование дескрипторов, `CLOEXEC`, переназначение стандартных потоков и каналы для протокола запуска Go.
- [x] Ожидание и код выхода через совместимый с Go интерфейс Linux; ошибки запуска и завершение без утечек.
- [x] Утилита `/bin/clear` в ramdisk и `PATH=/bin`. **Проверка:** тетрис создаёт `exec.Command("clear")`, задаёт `cmd.Stdout = os.Stdout` и вызывает `cmd.Run()`; команда пишет последовательность очистки в терминал, родитель продолжает работу.
- [x] Сквозные тесты успешного запуска, ошибок и повторных запусков в QEMU под UEFI и BIOS.

## Этап 3. Тетрис — сделан, проверен на реальном компьютере {#stage-3}

Устройство — [тетрис](architecture/tetris.md). Вызов внешней команды очистки в тетрисе сохранён.

В репозитории тетриса:

- [x] Одиночный режим ([PR №16](https://github.com/vszholobov/Tetris/pull/16)).

В ядре:

- [x] `/dev/tty`: режимы терминала через `ioctl`, ввод через последовательный порт и ожидание ввода через планировщик.
- [x] Тетрис в ramdisk, запуск командой `tetris` из [оболочки](architecture/shell.md). **Проверка:** тетрис играется в QEMU и возвращает в приглашение.
- [x] Минимальная оболочка: `help`, `ls`, `cat`, запуск исполняемых файлов, внешний `clear` и повторный запуск игры.
- [x] Автотест в CI: нажатия через последовательный порт, проверка вывода.
- [x] Для framebuffer: управляющие последовательности в консоли и глиф «Ж»; одиночное поле использует ASCII.
- [x] Ввод с PS/2-клавиатуры в `/dev/tty`; игровое управление на компьютере подтверждено владельцем 2026-10-14.

**Проверка на компьютере:** владелец подтвердил работу тетриса; точная модель и BIOS/UEFI пока не записаны.

## Этап 4 (по желанию). Сеть и современное железо {#stage-4}

Сетевой тетрис реализован и проверен в QEMU с локальным сервером из репозитория. Устройство — [сеть](architecture/core/network.md) и [Ethernet](architecture/drivers/ethernet.md), запуск — [пользовательская инструкция](../user/network.md).

- [x] PCI и поиск сетевой карты; аппаратные драйверы в `src/drivers/`.
- [x] Intel 82574L (`e1000e`) в QEMU, DMA-кольца RX/TX.
- [x] Драйвер Realtek RTL8168 G/GU/H/M для PCI ID Acer `10ec:8168`, диагностика XID; общий DMA-путь, DHCP и игра проверены через C+ в QEMU. PHY ноутбука ещё не проверен.
- [x] ICMP ping, DNS-запросы и диагностика сети/PCI.
- [ ] Wi-Fi QCA6174 WPA2 на Acer: [план](design/wifi.md); ROM-пробник реализован, аппаратная проверка ещё требуется.
- [x] smoltcp: DHCP, IPv4 и TCP.
- [x] Исходящие сокеты Linux и режимы `epoll`, необходимые Go.
- [x] `/etc/hosts` в ramdisk; настраиваемый адрес сервера клиента.
- [x] Настоящий сервер Tetris на локальном порту: два игрока, ход, поля, ping/pong, выход и повторный запуск без утечек; UEFI и BIOS.
- [ ] Сеть на реальном Acer: PCI ID определён, нужны проверка XID, запуск PHY и игра по кабелю с DHCP. Samsung пока вне задачи.
- [ ] Подключение к публичному серверу после его запуска владельцем.
- [ ] Запуск на [Acer Nitro](../user/hardware/acer-nitro.md) через UEFI.
