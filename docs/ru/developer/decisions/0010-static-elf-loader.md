# 0010. Свой загрузчик статических ELF

**Для кого:** для тех, кто трогает загрузку программ.

**Коротко:** OSel загружает только статические исполняемые ELF64 (`ET_EXEC`) своим небольшим парсером в `osel-core`. Загрузчик не трогает таблицы страниц, а просит трейт `ProgramMemory` отобразить обнулённые страницы и записать байты, поэтому целиком проверяется на хосте. Стек главного потока отображается сразу. Устройство — в [программах](../architecture/core/programs.md).

**Статус:** принято. **Дата:** 2026-10-12.

## Контекст

Цель этапа 2 — статическая Go-программа ([решение 0005](0005-linux-abi-for-go.md)). Go с `CGO_ENABLED=0` собирает `ET_EXEC` с тремя сегментами `PT_LOAD` без интерпретатора. Разбор ELF — вход недоверенных данных, его нужно проверять на сломанных файлах, а тесты в QEMU для этого медленные.

## Решение

- **Свой парсер**, только нужные поля заголовка и заголовков программы, все проверки — `ENOEXEC`.
- **Только `ET_EXEC`, без `PT_INTERP` и `PT_DYNAMIC`.** Динамическая компоновка и PIE не нужны ни Go, ни тестовым программам на ассемблере.
- **Трейт `ProgramMemory`** с двумя операциями вместо прямой работы с `UserSpace`: тот же код грузит в поддельную память на хосте, проверка идёт байт в байт и под фаззингом.
- **Записываемый исполняемый сегмент или такая общая страница — отказ.**
- **Стек 256 КБ отображается сразу.** Отображение по требованию появится вместе с обработчиком page fault для `mmap`.

## Рассмотренные альтернативы

- **Крейт `xmas-elf` или `goblin`.** Разбирают больше, чем нужно, а проверки диапазонов всё равно пришлось бы писать самим. Отвергнуто: свой разбор короче проверок к чужому.
- **Загружать прямо в `UserSpace` без трейта.** Проверка только в QEMU и без фаззинга. Отвергнуто.
- **Отображать сегменты прямо из ramdisk.** Данные в cpio не выровнены по странице. Отвергнуто.
- **Поддержать PIE (`ET_DYN`).** Нужна релокация базового адреса и `AT_BASE`. Отложено: Go по умолчанию собирает `ET_EXEC`.

## Последствия

- Программа на C, собранная с `-static-pie`, или динамическая не загрузится: `ENOEXEC`.
- Каждая программа сразу занимает 256 КБ под стек, пока нет отображения по требованию.
