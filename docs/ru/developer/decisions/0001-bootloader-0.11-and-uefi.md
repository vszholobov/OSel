# 0001. Загрузчик bootloader 0.11 и загрузка через UEFI

**Для кого:** для разработчиков, которые меняют загрузку и интерфейс BootInfo.

**Коротко:** OSel грузится загрузчиком `bootloader` 0.11, который умеет и UEFI, и BIOS. Поэтому вместо VGA текст выводится в framebuffer, а образ диска собирает свой инструмент `runner/` вместо `bootimage`.

**Статус:** принято. **Дата:** 2026-10-11.

## Контекст

Цель проекта — запускать систему на реальных ноутбуках. Старая версия `bootloader` 0.9 умеет только загрузку через BIOS. Многие современные машины загружаются только через UEFI: режим совместимости с BIOS (CSM) из них убран. Кроме того, старый крейт `x86_64` 0.14 перестал собираться на свежем nightly.

## Решение

- Загрузчик `bootloader` 0.11: один образ ядра, два образа диска — `OSel.uefi.img` и `OSel.bios.img`.
- Ядро собирается под встроенную цель `x86_64-unknown-none`, без своего JSON-описания цели.
- Вывод текста — в framebuffer (`osel-core/src/console.rs`, `src/avganec.rs`): под UEFI текстового режима VGA нет.
- Образы и запуск QEMU — `runner/` (`runner/src/main.rs`), он подключён как runner cargo через `runner/run.sh`.
- Тесты в CI гоняются в обоих режимах загрузки.

## Рассмотренные альтернативы

- **Остаться на `bootloader` 0.9 и BIOS.** Меньше изменений в старом коде. Отвергнуто: на UEFI-машинах без CSM система не загрузится.
- **Свой загрузчик или Limine.** Свой загрузчик требует больше работы; `bootloader` 0.11 уже закрывает обе прошивки. Limine остаётся вариантом позже, для меню выбора рядом с Windows.

## Последствия

- Код памяти и обработку `BootInfo` пришлось обновить: другой способ получить карту памяти и смещение физической памяти.
- Загрузчик оставляет в регистре SS свой селектор и свои страницы в нижней половине адресов — см. [прерывания](../architecture/core/interrupts.md) и [память](../architecture/core/memory.md).
- Для UEFI в QEMU нужна прошивка OVMF, её скачивает `runner/`.
