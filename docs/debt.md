# Техдолг

**Для кого:** для тех, кто выбирает, что улучшить, или натыкается на странное ограничение.

**Коротко:** здесь каждое отложенное решение — одна строка: что отложено, почему и где подробности. Подробности живут на странице подсистемы, здесь только ссылка. Сделанный пункт удаляется.

| Что | Почему отложено | Где |
|---|---|---|
| Теневой буфер для прокрутки консоли | прокрутка читает весь экран из видеопамяти, на реальном железе это медленно; в QEMU не заметно | [консоль](architecture/drivers/console.md) |
| Backspace на предыдущую строку | решится вместе с терминалом этапа 3 | [консоль](architecture/drivers/console.md) |
| Отдельные стеки для #GP | осторожно: page fault на отдельный стек переносить нельзя, ему понадобится вложенность | [прерывания](architecture/core/interrupts.md) |
| Проверки `cargo fmt` и clippy в CI | включение форматирования переформатирует весь код, отдельный PR | [тулчейн и CI](guides/toolchain-and-ci.md) |
| KVM в CI | быстрее, но меняет поведение таймера; нужна хотя бы одна задача без KVM | [как устроены тесты](architecture/testing.md#ci) |
| Фильтр тестов `cargo test -- <фильтр>` | тестовое ядро не умеет выбирать тесты по имени | [runner](reference/runner.md#test-args) |
| Куча фиксирована, 16 МБ | не растёт; рост потребует брать `MEMORY` под `ALLOCATOR` | [память](architecture/core/memory.md#heap), [блокировки](architecture/core/locking.md#pitfalls) |
| Драйвер часов реального времени | нужен для `clock_gettime`; тесты форматов из курса ШАДа ждут его | [этап 2](design/stage-2-user-mode.md), [курс ШАДа](nikka.md) |
| Свой ramdisk у отдельного тестового ядра | у всех ядер один `ramdisk/` и одни программы в `/bin`; нужен для тестов загрузки без ramdisk или со сломанным | [файлы и ramdisk](architecture/core/fs.md), [этап 2](design/stage-2-user-mode.md) |
| Символьные ссылки и файлы устройств в cpio | ядро понимает только файлы, жёсткие ссылки и каталоги, остальное отклоняется | [файлы и ramdisk](architecture/core/fs.md#cpio) |
| Кэш узлов файловой системы | `lookup` каждый раз создаёт новый объект узла; для ramdisk это дёшево, для диска нужен кэш | [файлы и ramdisk](architecture/core/fs.md#pitfalls) |
| Тест загрузки без ramdisk и со сломанным ramdisk | runner всегда кладёт правильный архив, а выбирать ramdisk для отдельного ядра он пока не умеет | [файлы и ramdisk](architecture/core/fs.md#invariants) |
| Блокировки на адресное пространство и дескрипторы процесса | пока у процесса один поток, их трогает только он; нужны вместе с `clone` | [потоки и планировщик](architecture/core/threads.md#invariants) |
| Отображение файлов в `mmap` | Go статической сборки его не использует; сейчас `ENODEV` | [память](architecture/core/memory.md#areas), [решение 0016](decisions/0016-lazy-anonymous-memory.md) |
| Содержимое файла после `MADV_DONTNEED` на сегменте программы | сегменты — анонимная память, и такая страница читается нулями, а Linux прочитал бы файл; Go так не делает | [память](architecture/core/memory.md#areas) |
| Страницы буфера системного вызова по мере копирования | `check_user` отображает весь буфер сразу; при огромном буфере в свежей памяти это лишние страницы, `read` ограничен 64 КБ | [память](architecture/core/memory.md#areas) |
| `os.Open` и `os.ReadFile` из Go | Go регистрирует каждый файл в netpoller, без `epoll` падает | [этап 2](design/stage-2-user-mode.md#syscalls) |
| Ввод терминала из последовательного порта и режимы терминала | терминал читает только клавиатуру PS/2 и без дисциплины строки; это этап 3 | [открытые файлы](architecture/core/fs.md#open-files) |
| Скрипт записи образа на флешку | отложен до проверки на ноутбуке, пока вручную | [запуск с флешки](start/usb.md) |
| Проверка на ноутбуке | нужен владелец с флешкой и машиной | [план](roadmap.md) |
