# 0009. Общая верхняя половина адресных пространств

**Для кого:** для тех, кто трогает адресные пространства программ или таблицы страниц ядра.

**Коротко:** у каждой программы своя таблица уровня 4. Её 256 записей верхней половины копируются из таблицы ядра и указывают на таблицы уровня 3, общие для всех пространств; ядро создаёт их все при загрузке. Удаление пространства обходит только нижнюю половину. Ошибки отображения откатываются явно, `FrameGuard` не нужен. Устройство — в [памяти](../architecture/core/memory.md#address-spaces).

**Статус:** принято. **Дата:** 2026-10-12.

## Контекст

Этапу 2 нужны адресные пространства программ: ядро должно работать в каждом из них, а после завершения программы все её страницы должны вернуться в пул ([решение 0008](0008-frame-pool.md)). Ядро живёт в верхней половине ([решение 0006](0006-higher-half-kernel.md)) и продолжает отображать новое после того, как пространства созданы: стеки потоков, рост кучи. Решение 0008 отложило `FrameGuard` до этого шага.

## Решение

- **Записи уровня 4 верхней половины копируются, таблицы уровня 3 общие.** При загрузке ядро создаёт пустую таблицу уровня 3 для каждой пустой записи верхней половины, около 250 страниц. После этого записи уровня 4 не меняются, и любое отображение ядра, сделанное позже, видно во всех пространствах без синхронизации.
- **Флаги этих записей — `PRESENT | WRITABLE`,** как у записей загрузчика. Страницы ядра не бывают `USER_ACCESSIBLE`, поэтому `map_to` никогда не расширяет флаги записей уровня 4, и копии не расходятся с оригиналом.
- **Удаление обходит только нижнюю половину** и возвращает в пул все её страницы и таблицы. Верхняя половина не принадлежит пространству.
- **Пустые таблицы освобождает свой обход** (`prune_empty_tables`), который никогда не освобождает таблицы уровня 3 верхней половины и таблицы не из пула.
- **Откат явный, без `FrameGuard`.** `map_range` при ошибке сам снимает свои страницы и возвращает их в пул. Утечки ловят тесты, которые исчерпывают страницы на каждом шаге.

## Рассмотренные альтернативы

- **Копировать таблицы ядра в каждое пространство, как в курсе ШАДа.** Отображение ядра, сделанное после создания пространства, туда бы не попало, а каждое пространство стоило бы копии всех таблиц ядра. Отвергнуто.
- **Синхронизировать записи уровня 4 при каждом новом отображении ядра.** Нужен список всех пространств и обход под блокировкой. Отвергнуто: 1 МБ на заранее созданные таблицы дешевле.
- **`clean_up_addr_range` из крейта `x86_64`.** Освобождает любую пустую таблицу, в том числе общую таблицу уровня 3, после чего все пространства ссылаются на освобождённую страницу. Отвергнуто.
- **`FrameGuard`, который держит `&mut` на пул.** Мешает передать тот же пул в `map_to`. Отвергнуто.
- **`FrameGuard`, который нужно явно потребить, иначе паника в `drop`.** Паника в `drop` ловит утечку только во время работы, а тесты с нехваткой страниц на каждом шаге — заранее. Отвергнуто.

## Последствия

- `map_range` обнуляет все страницы, в том числе 16 МБ кучи при загрузке.
- Ядро не может завести новую запись уровня 4 в верхней половине после загрузки: все они уже заняты, новые отображения идут в существующие таблицы уровня 3.
- Страница не из пула, отображённая в нижнюю половину (например, framebuffer программе), уронит `destroy`. Если такое понадобится, нужна пометка «страница не своя» в записи таблицы.
