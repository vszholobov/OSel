# 0011. Запуск программы до исключения и заглушки входа

**Для кого:** для тех, кто трогает вход в программу, исключения или будущие системные вызовы.

**Коротко:** `user::run` входит в программу через `iretq` со стека ядра вызывающего и возвращается, когда программа вызвала исключение. Указатель этого стека — одна статическая переменная и RSP0 TSS, без `swapgs`. Векторы исключений указывают на заглушки: из кольца 0 они прыгают в прежние обработчики, из кольца 3 собирают полный `TrapFrame`. Устройство — в [пользовательском режиме](../architecture/core/user-mode.md).

**Статус:** принято. **Дата:** 2026-10-12.

## Контекст

Шаг 4 этапа 2 должен запустить код в кольце 3 и пережить любое его исключение, сохранив все регистры программы. Потоков и планировщика ещё нет (шаг 8), процессор один. Обработчики исключений ядра — функции `x86-interrupt`, и на них держатся все тесты падений.

## Решение

- **Запуск до исключения.** `run` сохраняет callee-saved регистры и флаги на стеке ядра и выходит в программу. Возврат — прыжком из `user_trap` на сохранённый стек. Этого хватает, пока программа одна и не делает системных вызовов; на шаге 8 вместо возврата придёт переключение потоков.
- **Без `swapgs` и GS.** Указатель стека ядра лежит в статической переменной и в RSP0 TSS. Процессор один, а обработчики `x86-interrupt` не умеют делать условный `swapgs`.
- **Заглушки разводят кольца.** Для кольца 0 — прыжок в прежний обработчик с нетронутым стеком: исключения ядра ведут себя как раньше. Для кольца 3 — полный `TrapFrame` со всеми регистрами.
- **Аппаратные прерывания из кольца 3 — прежние обработчики.** Регистры, которые они портят, обработчик `x86-interrupt` сохраняет и восстанавливает сам. Вытеснение по таймеру потребует провести и IRQ 0 через заглушку.
- **Стеки IST (double fault, NMI, machine check) — без заглушек:** из кольца 3 они по-прежнему паникуют.

## Рассмотренные альтернативы

- **Проверять кольцо внутри обработчиков `x86-interrupt` и выходить оттуда.** Такой обработчик сохраняет только те регистры, которые портит сам, и неизвестно где. Регистры программы при исключении не восстановить. Отвергнуто.
- **Свой ассемблерный вход для всех векторов и разбор на Rust для обоих колец.** Пришлось бы переписать обработку исключений ядра и все тесты точного адреса падения. Отвергнуто: заглушка с прыжком меняет только путь из кольца 3.
- **Стек ядра на программу в RSP0 и GS с данными процессора, как в Linux.** Нужен с потоками и несколькими процессорами. Отложено до шага 8.

## Последствия

- Программа не может ни ждать, ни быть вытесненной: она работает, пока не вызовет исключение. Системные вызовы на шаге 5 добавят вход через `syscall` с тем же `TrapFrame`.
- `run` нельзя вызывать с выключенными прерываниями и внутри блокировок, это проверяется.
- Новое исключение, которое может вызвать программа, получает заглушку через `entry_stub`, иначе исключение из кольца 3 уронит ядро.
