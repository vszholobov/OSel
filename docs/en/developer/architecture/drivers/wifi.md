# QCA6174 Wi-Fi

**Audience:** hardware and firmware bring-up developers.

**Summary:** a hardware probe targets Acer `168c:003e`, subsystem `11ad:0807`, revision `32`. `wifi probe` attempts BMI Target Info after PCI/D0/wake, cold/warm reset and CE0/CE1/CE7 setup and ROM early configuration. `wifi load` also uploads firmware and checks HTC/WMI ready, then stops the target. `wifi scan` passively discovers APs in 2.4 GHz and selected 5 GHz channels; Acer photos confirm HTT 3.87 and an 18-AP list with Galaxy S23; repeat-series reliability remains unverified. `wifi connect N` implements WPA2 association and HTT/Ethernet/DHCP; `wifi disconnect` stops the card. The owner confirmed Acer connectivity, ping and a network game with a Mac; sustained stability remains under test.

## How it works {#how}

Only a shell command starts probing. Exact PCI IDs/revision and firmware/board containers are checked first. BAR0 must be 1 MiB aligned with the required span below 4 GiB. Direct-map MMIO pages become uncached. The adapter enters D0 without ASPM/CLKREQ; SOC_WAKE is asserted and RTC=ON is checked with a deadline.

QCA6174 uses cold reset, target-initialized waiting and warm reset. A global-reset write is followed by 20 ms without PCIe reads. PCI command disables INTx and CE interrupts are masked. ROM waiting repeats the PCIe core event-enable write to address a register-mapping race, while host INTx stays disabled. Missing/crashed targets return errors rather than waiting forever.

Nine zeroed DMA pages below 4 GiB hold CE0 source, CE1 destination, request, response and both diagnostic CE7 rings, a CE2 ring, and CE3/CE4 TX rings. After ROM, another 32 KiB holds 16 independent 2048-byte WMI buffers. CE2 publishes 15 descriptors, keeping one slot empty; completed buffers are copied before clearing and reusing them. This replaces a single published buffer, which could not absorb scan-event bursts between polls. CE7 has two entries; it reads `hi_interconnect_state` and writes target pipe config, the service map, L1 disablement and early allocation for the nine IRAM banks of hw3.2. After setting and reading back `HI_OPTION_EARLY_CFG_DONE`, PCIe core control signals the target CPU. Only then is BMI attempted; `target initialized=2` alone does not mean BMI is ready. Target RAM pointers are checked for alignment and bounds before DMA. Host setup preserves the ROM-owned halves of CE0/CE1. The BMI probe uses 16-entry rings with 8-byte descriptors and publishes one request. BMI GET_TARGET_INFO returns 12 bytes: size, target version and type. Only version `0x05030000` is accepted currently; another version is recorded and returns `EOPNOTSUPP`. `wifi probe` stops without BMI_DONE; `wifi load` continues as described below.

`wifi load` uses BMI commands of at most 256 bytes: EFUSE-selected PLL, host-interest/endianness, exactly 8124 bytes of the selected board, OTP and the main SGMT image through an LZ stream. Its last word is zero-padded and a zero-address stream flushes ROM caches. OTP status respects the bundled firmware IGNORE_OTP_RESULT feature. OTP execution calibrates the target; no flash/OTP programming commands are used. CE1 RX is posted before BMI_DONE; HTC ready is checked for endpoint, lengths, message ID, credits and credit size. HTC then connects HTT/WMI services and sends SETUP_COMPLETE_EX. CE2 may first receive WMI SERVICE_AVAILABLE (ID 3, TLV `0x22f`, 20 bytes), then SERVICE_READY (ID 1). `wmi::wait_service_ready` validates the preliminary message lengths and continues waiting: its extended service bitmap is unused by this station driver and does not establish readiness. At most 32 events share one five-second deadline, which is never restarted for each packet. Only SERVICE_READY passes the ABI, RF-chain, base-service and bounded memory-request checks. INIT advertises only owned, zeroed memory below 4 GiB; unit counts match vdev/peer resources. Limits are 1 MiB per request and 8 MiB in total. WMI ready requires matching ABI, successful status and a valid MAC. This does not establish association or connectivity. Progress appears every 64 KiB; a 120-second deadline follows the ROM check, with Ctrl+C cancellation.

An HTC trailer is a sequence of records: each header is four bytes (`id`, `len`, two padding bytes), and each credit report is also four bytes (`endpoint`, `credits`, two padding bytes). The length excludes the header. Padding is never interpreted as another endpoint or record; unknown records are skipped with bounds checks. A trailer-only packet returns credits without becoming a WMI/HTT event. Receive failures record the CE, length and HTC header; HTT version parsing records the reply length and first words.

Before freeing DMA, PCI bus mastering is disabled, events are masked, rings are halted and their sizes cleared. Timeout paths use the same teardown. After `wifi load`, cold reset stops the target CPU before freeing DMA, including error and cancellation paths. The probe is not attached to smoltcp and does not change Ethernet. Subsequent Wi-Fi bring-up needs reinitialization.

`wifi scan` creates a station vdev and runs three passive passes with distinct scan IDs in one firmware session. Results merge by BSSID and survive a later pass missing the AP. The list respects factory channel limits: 2.4 GHz channels 1–13 and 5 GHz channels 36–48 and 149–165 in steps of four. DFS and channel 14 are excluded. Every channel is passive with zero requested power; active probe requests are never enabled. Passive dwell is 200 ms per channel; distinct scan IDs and TLV FILTER_PROBE_REQ polarity follow the ABI. Each pass shares a 15-second deadline and a 4096-event limit; the overall 120-second load deadline remains. Foreign-channel/exit events are requested alongside started/completed/start-failed. Durations, WMI events, channel visits, management frames, rejected WMI/beacons and AP counts are retained, so an empty result is no longer the only diagnostic.

WMI events use bounded queues; HTC trailers from both CE1 and CE2 replenish credits, and TX buffers are not reused before DMA completes. Beacon/probe-response parsing checks SSID/BSSID, IE/RSN lengths, CCMP/PSK and mandatory PMF. Malformed frames are skipped and AP storage is capped at 20. SSID control characters are escaped. `station::unsupported_reason` drives both output and connection admission, explaining missing RSN, group/pairwise CCMP, PSK, mandatory PMF, hidden SSIDs, basic rates and connection channel restrictions. Discovery on extra channels does not authorize association there: STA still accepts only channels 1–11. Results are copied from WIFI_SCAN before output. The target stops after the command.

The AP channel comes from DS Parameter Set (IE 3), or HT Operation (IE 61) when DS is absent. WMI RX frequency is used only when neither element is present: in 2.4 GHz the receiver can hear neighboring-channel beacons, so the receive frequency need not be the AP channel. The corrected frequency is stored in scan results and used for admission, the channel table and VDEV_START. Empty/truncated, duplicate, conflicting and cross-band channel elements are rejected. After this correction, the owner confirmed Wi-Fi connectivity, ping and a network Tetris game between Acer/OSel and a Mac through a Yandex Cloud server. Sustained stability remains under test.

## HTT and connection {#station}

After WMI ready, HTT version verification and RX-ring publication, `wmi::station::configure_chains` programs TX_CHAIN_MASK and RX_CHAIN_MASK with separate PDEV_SET_PARAM commands, matching ath10k startup. The mask `(1 << chains) - 1` comes from validated SERVICE_READY capabilities (1–4 RF chains); two advertised chains produce `0x3`, without probing antenna combinations or changing calibration. Both steps precede scan/station vdev creation; any send failure stops startup, and partial setup is not success. Reports retain `WMI runtime TX/RX chain mask configured` and, on station failure, `STA runtime TX/RX chain mask`. These confirm command submission, not actual enabled radio paths or ACK reception. The compact failure snapshot omits the repeated power setting to keep rejected HTT/WMI headers within its last 22 lines; the initial `STA configured TX power half-dBm` remains in the setup log. C fixtures verify both two-chain commands; tests cover masks 1/3/7/15, invalid chain counts and failure at either command.

`wifi load` also verifies HTT version 3 and posts the RX ring: 128 entries, 63 buffers of 2048 bytes and a 300-byte v1 descriptor. The layout was checked against ath10k v6.12 `sizeof/offsetof`. TX buffers stay pinned until HTT completion, even after CE consumes their commands. HTT TX_CREDIT_UPDATE notifications (ID `0x0f`, at least four bytes) may precede the version response: they are validated and skipped because the driver uses TX completions without HTT credit flow control. `htt::wait_version` allows at most 32 packets under one three-second deadline; other events and malformed messages fail. The major version must still be 3. Malformed/duplicate completion IDs and unknown RX DMA addresses are rejected. RX checks MSDU_DONE, lengths, BSSID, FCS/MIC/decrypt errors, Ethernet decap and per-key/TID CCMP PN. The initial STA does not negotiate HT/VHT/A-MSDU/802.11 fragmentation. Descriptor-less offload accepts only EAPOL for subsequent WPA2 verification, never application traffic.

`wifi connect N` selects a saved AP, reads a password without echo and derives the PMK. A fresh firmware boot creates the station vdev and DEFAULT peer, sets its channel, then performs open authentication and association with SSID/legacy rates/RSN. Start response, peer map, AP replies and AID are required. WMI installs PTK/GTK; HTT SEC_IND acknowledges installation. After M4 TX and peer authorization, a kernel worker owns the card. Supported APs have a visible WPA2-PSK/CCMP SSID on channels 1–11 without mandatory PMF; power is capped at 10 dBm, using 11g/20 MHz. CPUID gates RDRAND, with bounded retries and stuck-source checks and no pseudorandom fallback.

Before auth, create `WMI_PEER_TYPE_DEFAULT`, matching ath10k STA_NONE. BSS type is not a substitute for a normal station peer. Vdev TX encapsulation stays Native WiFi even with Ethernet offload: each HTT descriptor selects management or Ethernet format. C fixtures use enums from `wmi.h` and `hw.h`, binding these policy choices alongside layout.

Every fresh firmware boot receives WMI SCAN_CHAN_LIST with the selected home channel, then PDEV_SET_REGDOMAIN, PDEV_SET_PARAM for 2.4 GHz power, VDEV_SET_PARAM for the management rate and VDEV_START. `wmi::station::start_with_channel` stops on any send failure. The Acer's confirmed EEPROM domain `0x6c` (WORC_WORLD) fills all three domain fields; both band CTLs are NO_CTL (`0xff`), matching the pinned ath table. This does not select a country: only audited domain `0x6c` is accepted, optionally with WORLDWIDE_ROAMING (`0x4000`), which is stripped before sending. Other domains, including country-coded values, return EOPNOTSUPP before the first station-configuration command. The channel passes the existing AP admission and factory-limit checks and uses MODE_11G, 20 MHz and a 10 dBm cap without PASSIVE. This does not initiate scanning. The previous `wifi scan` channel table does not survive card stop/reset; discovery itself remains passive. C fixtures cover the table and domain command; tests cover ordering, send failures, channels 1–11 and rejection before the first command.

Before start, the channel and PDEV receive the same 10 dBm ceiling (`20` in half-dBm units). The `wmi_channel` max_power, reg_power and max_tx_power fields are populated; their previous zero values capped power at 0 dBm. The limit is below the audited WORC_WORLD ceiling of 20 dBm for channels 1–11; firmware continues applying the exact board calibration. Raw SERVICE_READY hardware min/max fields are not interpreted as dBm. `management_rate` selects the AP's lowest basic rate regardless of IE order, falling back to its lowest supported legacy rate when no basic bits are advertised. WMI MGMT_RATE takes a long-preamble CCK or OFDM hardware code, not a numeric Mbps value. Any setup failure stops the sequence before VDEV_START and auth. Reports retain `STA configured TX power half-dBm` and `STA management rate code`; these are submitted settings, not measured power or an ACK confirmation. C fixtures check all 12 rate codes, both channel structures and power/rate commands; tests cover unsorted basic rates, CCK/OFDM, absent basic bits and every send failure.

After the VDEV_START response, before AP peer creation and the first auth, `wmi::station::prepare_authentication` sends VDEV_SET_WMM_PARAMS for all four BE/BK/VI/VO queues. This STA does not negotiate QoS: every queue uses legacy 11g DCF contention — CWmin 15, CWmax 1023, AIFS 2, TXOP 0, without ACM/NoAck. It then sets RX_WAKE=WAKE, TX_WAKE=ALWAYS, PSPOLL=NO_MAX, UAPSD=0 and STA_PS_MODE_DISABLED. This explicitly configures queues and the active state. Any send failure stops setup before peer/auth. Independent C fixtures check complete commands, including reserved words between queues; a test covers ordering and failure at every step.

Failure snapshots retain `STA EEPROM domain` and `STA management services HTT/WMI`: bit 0 represents WMI service MGMT_TX_HTT and bit 1 represents MGMT_TX_WMI. Zero means those service bits were not advertised; it does not establish that the older HTT management path is absent. Reports retain SERVICE_READY information without reading a stopped card. `STA TX queues and wake configured=1` confirms submission of all queue/wake commands, not their execution or on-air TX. `STA last other WMI event ID` retains the last event ID other than start/management without printing its payload.

One AP may have multiple HTT peer IDs: the Galaxy S23 photo shows `0x0f` and `0x7f`. A bounded 2048-bit set (RX descriptor ID space) replaces the overwritten single ID. RX and SEC_IND accept any currently mapped ID of the selected AP; replay remains shared by AP/key. Unmap removes one ID; losing the last revokes authorization. Reassigning an ID to another MAC removes its old binding.

Alongside TX_COMPL_IND, the parser accepts HTT MGMT_TX_COMPLETION (`0x0e`), validating ID/status: the original event is 12 bytes, the extended event is 20. PPDU ID and ACK RSSI fields are unnecessary for releasing the buffer. It completes only an outstanding management buffer; a wrong type, unknown or duplicate completion cannot release DMA. Ordinary Ethernet completions do not print per packet. Auth/association separately record submitted TX ID, TX-completion wait and AP-response wait. Every wait failure, including event parsing or TX status errors, retains the firmware indicator, CE4/CE1/CE2 indices, WMI/management/HTT counters and final errno. Rejected HTT/WMI events retain their length and first word; TX completions retain up to three words including ID/status. Keys, EAPOL and RX frame payloads are never printed; the compact snapshot keeps the rejected header visible in the last 22 lines of `wifi regs`.

After a negative management completion (DROP/NOACK), the driver requests only PDEV statistics using REQUEST_STATS. UPDATE_STATS uses the TLV ABI with the original 180-byte `wmi_pdev_stats`, not the 10.4 layout. The report retains channel power, completion/MSDU/MPDU counters, WMM drops, hardware queued/reaped, underruns, aborts, excessive retries, illegal rates, TID allocation failures and TXOP overflows, plus raw firmware-advertised minimum/maximum power values. Counters cover the whole fresh firmware boot; they do not establish the cause of one frame failure. The request does not change radio settings or request peer/RX data and runs only after a negative completion; original TX timeouts and event-parse errors do not trigger it. Receive time after submission is limited to 500 ms, also respecting the operation deadline and Ctrl+C. Stats errors/timeouts never replace the original EIO; the report ends with the failed TX ID/status and original errno. Tests compare the request and every extracted field with C fixtures and cover truncation, duplicates, absent PDEV and invalid record counts.

Kernel scenarios exercise IDs `15/127` through SEC_IND and RX, shared replay, retained authorization after the first unmap and revocation after the last; management completions of both sizes release pinned auth buffers but cannot free an Ethernet slot or complete DMA twice. Invalid status preserves the buffer until a valid completion; reports omit key material and RX payloads. These checks do not confirm on-air auth.

Before EAPOL enters WPA2, its Ethernet source must be the selected AP and its destination must be this station, including after authorization. An encrypted frame relayed by the AP from another Ethernet source cannot initiate a key exchange. Other application frames require an installed key, authorization and PN checks.

`bridge.rs` exchanges Ethernet frames with smoltcp through queues capped at 64 packets; the driver retains EAPOL. Connection generations revoke stale TX tokens. Switching adapters requires no live TCP/ICMP/DNS handles and preserves monotonic socket IDs; the old device is freed outside NETWORK. Confirmed AP loss, peer kickout, DMA errors or `wifi disconnect` clear link, IP, route and DNS and abort TCP. DMA pages are zeroed after stop/reset and returned to the allocator. The load deadline is disabled only for the connected worker, which never consumes shell input.

An outstanding HTT TX expires after 5 seconds: its buffer stays pinned until reset, while the worker reports `HTT TX completion timeout`. CE/station waits check disconnect requests. The WMI command buffer is zeroed immediately after CE source completion so PTK/GTK do not remain in shared DMA. Invalid or overlong password input is consumed through the end of the hidden line, keeping its suffix out of shell input. Core/kernel tests cover these boundaries.

`WMI_ROAM_EVENTID` (`0xb001`) exposes vdev, reason and raw RSSI; events for other vdevs do not affect the station. `BEACON_MISS` (reason 2) on an authorized station starts `station::LinkMonitor`, retaining the connection during verification. Periodic checks are retained in `wifi regs` without printing over shell input. Without blocking the worker, it sends up to three unicast probe requests on the admitted home channel, one second apart under a fixed three-second deadline. Repeated beacon misses and a full TX ring cannot extend that deadline. An ACK for the probe itself, a valid beacon/probe response from the selected AP, or RX passing CCMP/replay validation confirms AP activity. Failed TX, other peers, a wrong channel and malformed frames are not responses. After 30 seconds without confirmed activity, verification repeats because firmware may report beacon loss only once. Probe DMA buffers remain pinned until their own HTT completion or reset and never consume ordinary traffic completions. On deadline expiry, the worker reports `STA AP liveness timeout` and closes the connection. Peer kickout, loss of the last peer and deauth/disassoc still close it immediately. Unused roaming reasons, including `HO_FAILED` (5), are retained in `STA WMI roam reason` and `STA WMI roam RSSI raw`, but do not establish loss of this association by themselves. A valid link-loss event is no longer described as malformed WMI.

## WPA2 {#wpa2}

`osel-core/src/wifi/wpa2.rs` provides a pure WPA2-PSK/CCMP state machine: PBKDF2-HMAC-SHA1, PTK derivation, MIC and AES key unwrap. Primitives come from RustCrypto; dependency licenses accompany every ramdisk at `/usr/share/licenses/WPA2-NOTICES`. Passwords accept 8–63 bytes or a 64-digit hexadecimal PSK; secrets use `Zeroizing`.

The state machine checks replay counters, ANonce, MIC and RSN/GTK KDEs. It returns keys once and requires an explicit acknowledgement of hardware installation and M4 transmission before authorization. M3 retransmissions resend M4 without reinstalling keys. Group rekey follows the same rule; moving an unchanged GTK to a different index is rejected. SNonce requires a cryptographic random source with no timer-based fallback. Hardware association and the background rekey handler use this state machine.

The kernel target sets `aes_force_soft`; SHA1 uses `force-soft`. AES-NI/SHA intrinsics using XMM would corrupt user thread registers. A kernel test runs PBKDF2 and AES unwrap with patterns in all 16 XMM registers and verifies preserved state under UEFI and BIOS. Host tests cover known PMK/PTK and RFC3394 vectors, M1–M4, retransmissions, group rekey, invalid MICs, nonces and replay counters.

## Firmware and board {#firmware}

`firmware/` contains unmodified `firmware-6.bin`, `board-2.bin`, license and required notice. `firmware/manifest.json` records source, date and SHA256; `tools/check-firmware.py` verifies exact bytes in CI. Board selection requires the exact LiteOn `11ad:0807` PCI entry and 8124 bytes, without fallback to another board's calibration.

The parser checks NUL-terminated magic, 4-byte alignment, nested TLVs, lengths and overflow. Duplicate mandatory fields are rejected. Bundled firmware contains WMI TLV=4, HTT=3 and OTP. `wifi fw` reports version and sizes; bundled does not mean running.

The runner always includes `/usr/share/licenses/ath10k/LICENSE` and `/usr/share/licenses/ath10k/NOTICE` and the adapted driver license `DRIVER-ISC`, including with custom `OSEL_RAMDISK`. These paths are reserved; replacement or a file occupying a parent directory causes a packing error. This requires no program installation on the owner's machine.

## Locks and invariants {#locks}

Atomic BUSY permits one probe. Its guard releases the flag on all ordinary returns. `WIFI_REPORT` protects only a copyable 64-record report; no sleeping, MMIO or printing occurs under it. The caller owns the probe; waits require enabled IRQs and must not run in an IRQ handler. `NETWORK` and `WIFI_REPORT` are not nested.

Each attempt clears the report first. The last completed stage and errno remain after the command returns. `wifi regs` shows the last 22 saved entries to fit the display, without new register reads. Before timeout cleanup it captures PCI command/BME, PCIe core control, ring bases/sizes, control/command, read/write indices and errors for the failing CE. `CE error status` masks `0x7e0`: the low bit of the raw register is not a DMA error. Stages are shown on the display and sent to COM1 before the whole probe finishes.

## Pitfalls {#pitfalls}

- QEMU does not emulate QCA6174. Green CI validates parsing, absent-card behavior and cleanup, not Acer PCIe/reset/CE.
- Without early config and CPU signalling, ROM may report initialized without consuming BMI. Never clear ROM-owned rings.
- PCI revision does not replace BMI target version; continued bring-up needs a hardware report.
- Enable bus mastering only after valid rings are published; never free active DMA.
- Never wait under `IrqSpinlock`: losing PIT turns a bounded timeout into a hang.
- Firmware API 6 differs from the HTT packet interface. Bundled files do not provide WPA2 or DHCP.
- Successful VDEV_START does not replace publishing a channel table after firmware boot. Saved scan results belong to the host; the target channel table does not survive reset.

A subsequent photo after successful play shows delayed disconnection: `WMI AP connection lost=0xb001`, event length `0x20`, errno `0x65`; reconnecting helps. The old report omitted the reason, so the photo cannot distinguish beacon miss (2) from handoff failed (5), both fatal in the previous handler. The new monitor and reason diagnostics remove immediate teardown on an unverified beacon miss; sustained operation with this change still needs Acer validation.

## ABI audit {#abi-audit}

The official [Qualcomm product brief](https://www.qualcomm.com/content/dam/qcomm-martech/dm-assets/documents/qca6174a-product-brief_87-yb799-1-c.pdf) describes QCA6174A capabilities, but not its firmware programming protocol. The software reference is the ISC-licensed [ath10k v6.12](https://github.com/torvalds/linux/tree/v6.12/drivers/net/wireless/ath/ath10k) declarations. Board data contains board-specific calibration rather than an ABI specification; the exact LiteOn `11ad:0807` selection and hashes in `firmware/manifest.json` are preserved.

| Checked | Reference and automated coverage |
|---|---|
| PCI/ROM, CE and BMI upload | `pci.c`, `hw.h`, `bmi.h`; existing ROM model and tests using actual firmware/board data |
| HTC and HTT startup | `htc.h`, `htt.h`; preliminary events, four-byte credit records, control/ready trailers, shared deadlines and event limits |
| WMI boot, scan, station and keys | `wmi.h`, `wmi-tlv.h/c`; complete binary commands, sizes, TLV tags, enum IDs, field order and zero padding |
| HTT RX/TX | `htt.h`, `rx_desc.h`; TX descriptors/prefetch, RX sizeof/offsetof, peer map/unmap, SEC_IND and TX completion |
| DMA ownership | UEFI/BIOS kernel scenario with real pages: RX buffer recycling, unknown addresses, duplicate completion, distinct PTK/GTK acknowledgements and peer loss |
| Radio input | Truncations, single-bit mutations of valid events and deterministic malformed packets; EAPOL bound to the selected AP, MIC/replay and known cryptographic vectors |

`osel-core/tests/wifi_abi.rs` reads fixtures in `osel-core/tests/fixtures/ath10k-v6.12/`. ```

`tools/wifi-abi-cases.c` defines synthetic examples; Python extracts declarations from verified headers, compiles them in a temporary directory and compares the bytes. `--update` regenerates fixtures after intentional scenario changes without bypassing source hashes. Ordinary `cargo test-core` requires no C compiler, network or Linux header installation.

These checks detect software ABI mismatches and event-handling errors. They do not model radio behavior, analog timing, RF-kill or internal state of the closed firmware.
